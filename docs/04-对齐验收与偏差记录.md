# 对齐验收与偏差记录

## 1. 职责

本文档只记录两件事：

```txt
1. VT Studio 和 Toonflow 哪里不一样
2. 每个功能最后是否对齐通过
```

不写功能过程，不写按钮清单，不写接口细节。那些内容写到 `features/` 和 `tasks/`。

## 2. 对齐原则

```txt
技术栈可以不同
代码结构可以不同
组件库可以不同
UI 可以更清晰
高风险实现可以换成更稳的实现
业务语义不能随意改
用户能做的事不能少
状态和失败原因不能少
数据关系不能凭空改
```

## 3. 必须对齐

每个功能验收时至少检查：

```txt
入口是否一致
页面区域是否完整
按钮/操作是否缺失
弹窗/表单字段是否缺失
默认值和必填规则是否一致
服务调用语义是否一致
参数和返回是否可对应
数据库读写是否可对应
本地文件读写是否可对应
任务记录是否完整
状态流转是否完整
轮询或 Socket 是否完整
模型调用参数是否完整
成功反馈是否完整
失败反馈是否完整
删除和级联影响是否清楚
```

## 4. 允许偏差

允许，但必须记录：

```txt
Electron/Vue/Tailwind/SCSS/TDesign 的实现差异
renderer -> preload -> main 的本地安全分层
不用 Toonflow 的 Express 路由形态，改为 Electron IPC 服务
运行数据不放项目目录，改放系统 userData/temp
登录弱化为本地优先
请求地址配置弱化为本地服务配置
剪映草稿导出属于 VT Studio 增强能力
命名拼写修正
更清楚的错误提示或交互布局
```

## 5. 不允许偏差

```txt
漏掉参考项目已有功能
漏按钮、漏表单字段、漏批量操作
漏失败原因、漏任务状态、漏轮询
把复杂流程做成静态占位
页面直接访问 SQLite、文件系统、模型 SDK
没看源码就按想象实现
为了省事改变业务语义
```

## 6. 已知基础偏差

| 编号 | 范围 | 偏差点 | 原因 | 结论 |
|---|---|---|---|---|
| D-BASE-001 | 技术栈 | 不复制 Toonflow 的前后端结构，VT Studio 使用 Electron main/preload/renderer | 本项目是本地桌面端，需要更清晰的本地能力边界 | 可接受 |
| D-BASE-002 | 运行目录 | Electron runtime/userData 不放项目目录 | 项目目录应保持干净，可提交内容和运行缓存分离 | 可接受 |
| D-BASE-003 | API 形态 | 不直接照搬 HTTP routes，业务语义映射到 `window.vtStudio` IPC 契约 | renderer 不能直接碰 Node，本地桌面更适合受控 IPC | 可接受 |
| D-BASE-004 | 登录 | Toonflow 登录能力已弱化为本地优先 | 用户目标是本地创作工具，账号不是主链路；已由 D-BASE-013 和 CORE-010 收口 | 可接受 |
| D-BASE-005 | 导出 | Windows 剪映专业版草稿导出是新增增强能力 | VT Studio 的核心目标之一 | 可接受 |
| D-BASE-006 | 任务队列 | Toonflow 只有 `进行中/已完成/生成失败`，VT Studio 额外增加 `cancelled` | 后续长任务、模型生成、导出需要统一取消标记 | 可接受 |
| D-BASE-007 | 任务队列 | Toonflow 任务表只有 `startTime`，VT Studio 增加 `finished_at/created_at/updated_at` | 需要完整生命周期、排序、耗时统计和排查能力 | 可接受 |
| D-BASE-008 | 任务队列 | 启动时把遗留 `running` 任务改成 `failed` | 对齐 Toonflow `fixDB.ts` 的异常退出修复思路，避免任务永久卡住 | 可接受 |
| D-BASE-009 | 模型适配层 | 动态供应商代码只允许在 main 侧 vm2 沙盒执行 | 对齐 Toonflow 动态供应商能力，同时避免 renderer 接触 SDK、密钥和本地文件 | 可接受 |
| D-BASE-010 | 模型适配层 | ComfyUI 不硬编码进核心层，统一作为供应商 adapter 扩展 | 避免核心层绑定某个协议，后续 OpenAI Compatible、ComfyUI、火山、可灵等都走同一协议 | 可接受 |
| D-BASE-011 | 模型适配层 | 依赖使用参考项目同代 `ai@6/@ai-sdk`，不使用最新 `ai@7` | 当前开发环境是 Node 20.19，`ai@7` 要求 Node >=22；需要优先保证项目可运行 | 可接受 |
| D-BASE-012 | 媒体显示 | OSS 抽象改为本地受控 HTTP 媒体服务（127.0.0.1 + token + 随应用启停 + 真缩略图） | 参考项目用本地 HTTP 服务显示图片但裸奔，缩略图被注释；VT Studio 要导剪映，视频需 range 分段加载，统一走 HTTP 服务最省事且安全可控 | 可接受，见 CORE-012、00-公共底层 8.1.1 |
| D-BASE-013 | 登录 | 登录降级为本地默认用户，完整云账号体系后置 | 本项目本地优先，账号不是主链路；收口 C-BASE-001 | 可接受 |
| D-BASE-014 | 嵌入与记忆 | 嵌入沿用参考项目本地 ONNX（all-MiniLM-L6-v2），不走供应商 embedding 接口 | 本地优先：离线、零成本、不泄露创作内容；模型层不加 embedding 类型，文本摘要复用 CORE-007 | 可接受，见 CORE-011 |
| D-BASE-015 | 日志诊断 | 新增统一日志层，终端只显示中文短状态，详细对象写 runtime logs | 参考项目没有统一日志层；VT Studio 后续模型、任务、导出日志很多，必须先收口 | 可接受，见 CORE-013 |
| D-BASE-016 | 工程治理 | 新增 `verify:*` 分组入口和 `verify:docs` 文档状态校验 | Toonflow 没有多 AI 交接文档体系；VT Studio 要长期续做，必须把脚本入口、TODO 完成记录和 03 文档引用做成可验证规则 | 可接受，见 OPT-BATCH-001 |
| D-BASE-017 | 响应格式 | 参考项目为 `code/data/message`，VT Studio 固定 `code/data/msg`，并在失败 `data` 增加 `errorCode/msgKey/requestId` | `msg` 是用户确认过的统一字段；细分错误码和 requestId 用于多语言、日志追踪和后续任务中心诊断，不改变业务语义 | 可接受，见 OPT-027 |
| D-BASE-018 | 字典值 | 完成态固定为 `succeeded`，资产类型沿用 `role/scene/tool/clip/audio` | 这些 key 已经进入任务、资产、生产和页面状态，改成 `success/character/prop/segment` 会破坏现有数据；展示文案继续走 i18n，不把中文写进数据库 | 可接受，见 OPT-028 |
| D-BASE-019 | 状态分层 | 任务中心总体状态、业务对象状态、导出摘要状态分层维护 | 参考项目不同模块状态来源较分散；VT Studio 的本地长任务、批量生成、取消和启动恢复必须区分整体任务和单个对象，避免部分失败时误导用户 | 可接受，见 OPT-013 |
| D-BASE-020 | 业务锁 | 删除项目和数据库危险操作统一检查任务表与业务对象运行态 | 参考项目各模块检查分散；VT Studio 本地长任务会写多张业务表，必须统一阻断全局危险操作，避免任务完成后写入已删除对象 | 可接受，见 OPT-038 |
| D-BASE-021 | 默认资源治理 | 默认 Skill、手册、模型提示词、供应商 adapter 和 ONNX 路径集中到 VT Studio registry；旧 `driector_skills` 目录删除，新写入统一 `director_skills` | 参考项目默认资源分散且存在目录拼写旧痕迹；VT Studio 需要“文件、数据库、页面、链路”可诊断、可恢复，旧拼写只保留读取兼容 | 可接受，见 CORE-014 |
| D-BASE-022 | 模型能力矩阵 | 新增统一 `capabilityMatrix`，把模型 type、mode、输入限制、输出类型、时长、分辨率、音频支持和提示词模板类型集中表达 | 参考项目模型能力更多靠 vendor manifest 和页面逻辑分散读取；VT Studio 后续要同时支持普通连接、高级 adapter、项目默认模型、提示词映射和生产工作台，必须先统一能力来源 | 可接受，见 OPT-031 |
| D-BASE-023 | 视频提示词生成 | 参考项目 HTTP route 改成 Electron main service；模板读取顺序保留为模型/mode 映射、默认视频模板、`videoPromptGeneration` 兜底 | 技术栈不同但业务语义一致；renderer 不能直接调模型 SDK，必须走 main service 和任务中心 | 可接受，见 OPT-004 |
| D-BASE-024 | 模型连接投影 | 普通模型连接以 `modelConnections.v1` 为主数据，`model_vendors` 的 `conn_*` 只作为运行投影；高级 vendor 页只读展示投影 | 参考项目更多直接围绕供应商配置运行；VT Studio 需要普通用户入口更简单，同时底层调用继续统一走 vendor runtime，所以必须明确主数据和投影边界 | 可接受，见 OPT-053 |
| D-BASE-025 | 模型调用网关 | 文本、图片、视频、TTS 统一经过 main 侧 `model/gateway`，记录 requestId、协议、耗时和归一化错误 | 参考项目可以走 HTTP route 和 adapter 分散入口；VT Studio 是 Electron，本地密钥、SDK、SQLite 和文件必须留在 main，统一网关更适合后续取消、超时、重试和诊断 | 可接受，见 OPT-006 |
| D-BASE-026 | adapter 安全边界 | 自定义 adapter 仍支持动态代码和网络请求，但 `fetch/axios/urlToBase64/pollTask/logger` 都经过 main 侧安全包装 | 保留参考项目动态供应商能力，同时避免危险协议、无限初始化、无限轮询、超大下载和日志泄密；严格域名 allowlist 先作为底层能力保留，避免默认打坏临时素材域名 | 可接受，见 OPT-052 |
| D-BASE-027 | 模型运行治理 | 模型调用支持超时、有限重试、taskId 和取消检查；不能物理中断的第三方调用按“取消后不写成功”处理 | 不同 SDK/adapter 对 AbortSignal 支持不一致；VT Studio 先保证任务状态和业务落盘不被迟到结果污染，完整文件生命周期继续归 OPT-036 | 可接受，见 OPT-032 |
| D-BASE-028 | 模型请求可观测 | 新增设置页请求诊断，展示最近模型请求摘要，不照搬浏览器 Network 或后端 HTTP 日志形态 | Electron 桌面程序没有浏览器 Network 面板，renderer 也不能直接看 SDK 请求；VT Studio 需要内置 requestId、耗时、重试、状态和脱敏失败原因来排查模型问题 | 可接受，见 OPT-014 |
| D-BASE-029 | 本地请求诊断 | 新增本地服务、Socket、media 路由和本地请求失败摘要诊断，不把签名 URL、token、完整资源路径暴露给页面 | 参考项目以浏览器/后端形态排查请求；VT Studio 是桌面端，必须内置安全诊断能力，同时保持 renderer 不直接接触本地服务内部实现 | 可接受，见 OPT-015 |
| D-BASE-030 | 密钥安全边界 | renderer 不回传模型 API Key/vendor secret；编辑留空表示不修改；完整 SQLite 备份标记包含密钥，业务导出不带全局密钥 | 参考项目可在前后端配置中直接处理供应商参数；VT Studio 是本地桌面端，密钥只应留在 main/runtime 侧用于调用，页面、日志、诊断和项目导出必须默认脱敏 | 可接受，见 OPT-035 |
| D-BASE-031 | ComfyUI workflow | 参考项目没有完整 ComfyUI queue/history 实现，VT Studio 新增 `vt.comfyui.workflow.v1` manifest 和 main 侧 workflow 执行器；第一版只支持图片 workflow | 用户明确希望后续支持 ComfyUI，且 ComfyUI 必须有节点映射规范；不能把视频 workflow 伪装成已完成能力 | 可接受，见 OPT-033 |
| D-BASE-032 | 项目整体迁移包 | 参考项目只找到全库 JSON 备份/导入、剧本 zip、分镜图片 zip、视频批量下载 zip 和 WebAV mp4，未找到完整单项目迁移包；VT Studio 新增目录型 `.vtproject` 项目包 | 桌面创作工具需要单项目跨机器迁移，不能要求用户导出全库或手动拷贝数据库和素材；第一版用目录包而不是 zip，便于排查、恢复，也不新增压缩依赖 | 可接受，见 OPT-037 |
| D-BASE-033 | 流程总览 | 参考项目没有独立“项目流程总览”页，VT Studio 新增流程总览并联动任务中心失败筛选 | 用户需要一眼知道文字到视频做到哪一步；失败任务摘要只做入口提示，完整失败详情、分页、复制原因仍保留在任务中心，不改变业务语义 | 可接受，见 OPT-051 |
