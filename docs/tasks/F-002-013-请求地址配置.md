# F-002-013 请求地址配置

状态：已完成  
所属菜单：M-002 设置  
对应功能文档：`docs/features/M-002-设置.md`  
原则：先确认本文档，再改代码

## 0. 快速理解

```txt
一句话：处理本地服务地址相关配置，但不能把 VT Studio 做回“前端直连后端地址”的 Web 模式。
为什么现在做：参考项目是 Web + 本地 HTTP；当前 VT Studio 主链路已经改成 Electron preload/main IPC，不能照搬成普通用户可编辑的请求地址。
做完后有什么用：开发者能排查本地服务地址，普通用户不会误以为改一个 baseUrl 就能影响整个桌面应用。
这一步不碰什么：不改 IPC 主链路，不把页面重新改回直接 axios 访问后端。
```

## 1. 本次做什么

```txt
目标：
  对齐 Toonflow requestConfig 的能力，但明确 VT Studio 本地桌面版的边界。

只做：
  1. 显示当前本地服务地址
  2. 刷新 Electron 本地服务地址
  3. 只读诊断信息
  4. 开发者/高级模式显示控制

不做：
  1. 普通业务页面直接用 axios 调后端
  2. 生产环境鼓励用户改地址
  3. 远程云服务切换
  4. 普通可编辑请求地址
```

## 2. 参考项目怎么做

| 参考文件 | 关键逻辑 |
|---|---|
| `Toonflow-web/src/components/setting/components/requestConfig.vue` | warning alert、API 地址 input、保存、重置、Electron 刷新 |
| `Toonflow-web/src/stores/setting.ts` | baseUrl 本地持久化 |
| `Toonflow-web/src/utils/axios.ts` | axios 请求使用 baseUrl |
| `Toonflow-web/src/App.vue` | Electron 环境通过 `toonflow://getAppUrl` 获取本地服务地址 |
| `Toonflow-web/src/pages/login/index.vue` | 登录页也能设置 baseUrl |

参考项目关键事实：

```txt
1. store 默认值是 http://localhost:10588/api。
2. requestConfig 重置值是 http://localhost:10588，不带 /api。
3. 登录页 placeholder 也不带 /api。
4. VT Studio 必须统一 baseUrl 语义。
5. VT Studio 主链路应走 preload/main，不应该让普通页面绕开 IPC。
6. 当前 VT Studio renderer 里没有统一 axios baseUrl 消费链路，这意味着“请求地址配置”不能再按参考项目原样落地。
```

## 4. 要做什么功能

### 1. 显示当前 baseUrl

怎么做：
- 输入：无。
- 输出：当前 baseUrl。
- 写什么数据：不写。
- 状态怎么变：表单显示。
- 异常怎么处理：缺失时显示默认本地服务地址。
- 限制：明确 baseUrl 是否包含 `/api`，不能两套语义混用。

### 2. 刷新本地服务地址

怎么做：
- 输入：无。
- 输出：当前本地服务 URL。
- 写什么数据：不写。
- 状态怎么变：表单更新。
- 异常怎么处理：本地服务未启动时提示。
- 限制：不能使用 Toonflow 的 `toonflow://getAppUrl`，VT Studio 用 preload/main 能力。

### 3. 只读诊断信息

怎么做：
- 输入：无。
- 输出：`running / url / port / source / editable=false`。
- 写什么数据：不写。
- 状态怎么变：诊断卡片显示。
- 异常怎么处理：本地服务没起来时显示未启动。
- 限制：不能伪装成“用户可编辑请求地址”。

### 4. 显示控制

怎么做：
- 输入：是否开发者模式。
- 输出：显示/隐藏。
- 写什么数据：不写。
- 状态怎么变：普通用户默认不显示或只读。
- 异常怎么处理：无。
- 限制：避免用户改坏后整个应用请求失败。

## 6. VT Studio 怎么落

```txt
能力名：
  settings.request

调用链：
  renderer 设置页 -> window.vtStudio.settings.request -> main/ipc -> local server info

需要新增：
  设置页本地服务地址诊断组件
  request diagnostics 类型

需要修改：
  开发者模式挂载诊断入口
  生产主链路仍走 window.vtStudio

当前代码现实：
  1. 当前 renderer 主链路已改成 `window.vtStudio -> main/ipc -> services`。
  2. 当前项目里不存在参考项目那种“统一 axios 请求都读 baseUrl”的真实消费链路。
  3. 当前唯一接近“本地服务 URL”的能力是 main 侧本地 HTTP 服务，例如 media server URL。
  4. 所以这个功能如果继续叫“请求地址配置”，很容易误导用户。
```

## 7. 偏差

```txt
和 Toonflow 不同的地方：
  1. 不使用 toonflow://getAppUrl。
  2. 不做普通可编辑请求地址。
  3. 直接重定义为“本地服务地址诊断”。

原因：
  VT Studio 是 Electron 本地桌面应用，页面不应该依赖用户手填后端地址；当前架构下这个功能如果照搬会误导用户。

是否写入 04：
  需要写入 04，属于功能语义调整。
```
