# OPT-008 角色图和资产生成规则统一

## 通俗总结

这次不是重做资产页，而是把“资产图片到底是什么图”定死。

参考项目里，角色、场景、道具都写在 `o_assets`，图片历史写在 `o_image`，当前使用哪张图由 `o_assets.imageId` 指向。角色生成不是普通头像，而是“角色标准四视图”；场景是“标准场景图”；道具是“标准道具图”。

VT Studio 保留这个逻辑，但比参考项目多补一层追溯：每张图都要知道自己是主图、衍生图还是自定义图，用了哪个 prompt、哪个模型、哪个任务、什么分辨率，后面分镜和视频引用时不能拿错。

## 参考项目怎么做

| 参考位置 | 结论 |
|---|---|
| `Toonflow-app-master/src/routes/assetsGenerate/generateAssets.ts` | 单个资产生成图，先插入 `o_image(state=生成中)`，再把 `o_assets.imageId` 指过去 |
| `Toonflow-app-master/src/routes/assetsGenerate/batchGenerateImageAssets.ts` | 批量生成也是先插入图片占位，再异步生成 |
| `Toonflow-app-master/src/routes/assets/getImage.ts` | 历史图片按 `assetsId` 查，`selected` 由 `o_assets.imageId` 判断 |
| `Toonflow-app-master/src/routes/assets/saveAssets.ts` | 上传自定义图会插入一条图片记录，并更新当前图 |
| `Toonflow-app-master/src/routes/assetsGenerate/polishAssetsPrompt.ts` | 父资产和衍生资产使用不同视觉手册片段 |

## 要做什么

1. 统一资产图片用途：
   - `primary`：父资产主图。
   - `derived`：子资产/衍生状态图。
   - `viewSet`：预留给拆分方位图。
   - `reference`：参考图。
   - `custom`：用户上传或非生成来源。
2. 统一资产图片视图模式：
   - `fourView`：角色父资产标准四视图。
   - `standard`：场景/道具标准图。
   - `derived`：衍生资产状态图。
   - `custom`：用户自定义图。
3. `asset_media` 记录生成追溯字段：
   - `usage`
   - `view_mode`
   - `prompt`
   - `model_mode`
   - `task_id`
   - `metadata`
4. 资产图片生成时按参考项目包装 prompt：
   - 角色父资产生成“角色标准四视图”。
   - 场景父资产生成“标准场景图”。
   - 道具父资产生成“标准道具图”。
   - 子资产生成衍生图，并保留父资产关系。
5. 生产工作台生成衍生资产图片时，也写同样的追溯字段。

## 具体怎么做

1. 在 `src/shared/constants/dictionaries.ts` 增加 `ASSET_IMAGE_USAGES` 和 `ASSET_IMAGE_VIEW_MODES`。
2. 在 `src/shared/types/assets.ts` 给 `AssetMediaItem` 增加用途、视图模式、prompt、modelMode、taskId、metadata。
3. 在 `src/main/services/assets/migrations.ts` 增加 `0015_add_asset_media_generation_metadata`。
4. 在 `src/main/services/assets/service.ts`：
   - `resolveAssetImageRule()` 判断当前资产应该生成什么图。
   - `buildAssetImagePrompt()` 按参考项目包装最终图片 prompt。
   - `insertMedia()` 写入用途、视图模式和生成元数据。
   - `mapMediaRow()` 把这些字段返回给 renderer。
5. 在 `src/main/services/production/service.ts`：
   - 衍生资产图写 `usage=derived`、`view_mode=derived`。
   - 记录父资产、prompt、模型、分辨率和任务 ID。
6. 增加 `scripts/verify-opt-008-asset-image-rules.mjs`，并接入 `verify:assets`。

## 不做什么

1. 不把角色四视图拆成四张单独图片；参考项目也是一张“四视图”图。
2. 不在这一步重做资产页 UI。
3. 不在这一步完整接入视觉手册快照；这个归 `OPT-009` 和 `OPT-034`。
4. 不做图片文件孤儿清理；这个归 `OPT-036`。
5. 不做上游变更导致下游失效；这个归 `OPT-054`。

## 完成标准

1. 每个资产仍然通过 `assets.media_id` 指向当前使用图。
2. 每张资产图片都能知道用途和视图模式。
3. 角色父资产生成图的最终 prompt 包含“角色标准四视图”。
4. 场景/道具父资产生成图的最终 prompt 包含标准图规则。
5. 子资产和生产工作台衍生资产图写成 `derived`。
6. 图片历史能返回 prompt、model、resolution、taskId、metadata。
7. 生产分镜和视频引用资产时，继续优先读取当前选中图，不改变旧链路。
