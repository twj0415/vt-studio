# OPT-013 任务状态和业务状态分层

状态：已完成

## 0. 快速理解

一句话：任务中心只记录“一次异步工作”的总体状态，业务表记录“每个业务对象”自己的状态。

为什么现在做：后面图片、视频、导出、Agent 都是长任务。批量任务里可能 10 个对象成功、1 个失败，如果任务状态和对象状态混在一起，页面会误导用户。

做完后有什么用：任务中心看整体，业务页面看明细。后续新增异步功能时，先判断自己写 `tasks.status` 还是写业务对象状态，不再临时发明一套状态。

这一步不碰什么：不重做任务队列并发，不新增全局等待队列，不重构所有取消逻辑；并发锁和迟到结果治理继续归 `OPT-038/OPT-032`。

## 2. 状态怎么分

| 层 | 字段 | 状态值 | 用途 |
|---|---|---|---|
| 任务记录 | `tasks.status` | `waiting/running/succeeded/failed/cancelled` | 任务中心筛选、总体失败原因、启动恢复 |
| 原文事件 | `source_chapters.event_status` | `stale/running/succeeded/failed` | 章节事件是否过期、是否生成成功 |
| 剧本资产提取 | `scripts.extract_status` | `idle/waiting/running/succeeded/failed` | 剧本资产提取排队、运行、结果 |
| 生成业务对象 | `assets.prompt_status`、`assets.image_status`、`assets.audio_bind_status`、`asset_media.status` | `idle/running/succeeded/failed/cancelled` | 资产提示词、图片、媒体、音频绑定的对象级状态 |
| 生成业务对象 | `production_storyboards.image_status`、`production_video_tracks.status`、`production_videos.status` | `idle/running/succeeded/failed/cancelled` | 分镜图、视频轨道、视频候选的对象级状态 |
| 导出草稿 | `export_summary.status` | `validating/running/succeeded/failed` | 导出产物摘要，不反写生产业务对象 |

## 3. 具体怎么做

1. 创建任务时：
   - 只通过 `src/main/services/task/service.ts` 写 `tasks.status`。
   - 业务 service 调 `createTask/succeedTask/failTask/cancelTask`，不直接 SQL 更新 `tasks.status`。
2. 创建业务对象时：
   - 原文事件写 `SOURCE_EVENT_STATUS`。
   - 剧本资产提取写 `SCRIPT_EXTRACT_STATUS`。
   - 资产、分镜、视频写 `ASSET_TASK_STATUS/PRODUCTION_TASK_STATUS`。
   - 导出摘要写 `EXPORT_DRAFT_STATUS`。
3. 批量任务部分失败时：
   - 成功对象保留 `succeeded`。
   - 失败对象写 `failed` 和自己的失败原因。
   - 总任务按整体结果写 `failed`，失败原因写“多少项失败/哪类失败”。
4. 用户取消时：
   - 能取消的任务写 `cancelled`。
   - 已经生成成功的对象不回滚。
   - 仍在 running 的对象必须写 `cancelled` 或 `failed`，不能写成功。
5. 启动恢复时：
   - 残留 `tasks.running` 恢复为 `failed`。
   - 残留业务对象 running 由各业务模块恢复为 `failed`。
   - `waiting` 是否恢复为 failed 按业务语义决定；桌面端没有后台队列时不能长期保留 waiting。
