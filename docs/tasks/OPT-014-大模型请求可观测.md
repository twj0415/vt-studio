# OPT-014 大模型请求可观测

状态：已完成

## 0. 快速理解

一句话：让桌面程序里也能看到最近大模型请求，不用只能翻终端日志。

为什么现在做：Electron 桌面程序没有浏览器 Network 面板。图片、视频、TTS、文本 Agent 调模型失败时，用户至少要知道是哪个供应商、哪个模型、哪个任务、耗时多久、失败原因是什么。

做完后有什么用：设置里的“请求诊断”可以看到本地服务状态和最近模型请求摘要。每条请求都有 requestId、任务 ID、供应商、模型、协议、状态、重试次数、耗时和脱敏失败原因。

这一步不碰什么：不保存完整请求体/响应体；不显示 API Key；不显示完整本机路径；不把诊断流水写进数据库；不做 media 资源访问失败流水，那个继续留给 `OPT-015`。

## 1. 本次做什么

1. 新增模型请求诊断内存 store。
2. `runModelCall` 在开始、尝试、重试、成功、失败时写入诊断。
3. 诊断记录最近 80 条，防止内存无限增长。
4. 诊断记录只保留摘要：
   - requestId
   - taskId
   - vendorId / protocolVendorId / vendorName
   - modelName / modelType
   - protocol
   - status
   - startedAt / finishedAt / durationMs
   - attempt / maxAttempts / retryCount
   - error name/message/statusCode/msgKey
5. 错误信息脱敏：
   - API Key、token、authorization、password、secret
   - Windows/macOS 用户路径
   - 长错误文案截断
   - 不返回 stack
6. 扩展设置请求诊断返回值：
   - 本地服务状态继续保留
   - 新增 `modelRequests`
7. 设置页面显示“最近模型请求”表格。
8. 页面新增文案走 i18n，中英文都补齐。
9. 补 `MODEL_TIMEOUT(70007)` 的中英文状态文案。
10. 新增专项 verify，并接入 `verify:core`。

## 2. 要做什么功能：怎么做

| 要做什么 | 怎么做 |
|---|---|
| 记录最近模型请求 | 新增 `src/main/services/model/request-diagnostics.ts`，内存保存最近 80 条 |
| 调用开始可见 | `runModelCall` 开头调用 `recordModelRequestStart` |
| 每次尝试可见 | 每轮 attempt 调用 `recordModelRequestAttempt` |
| 重试可见 | 临时错误重试前调用 `recordModelRequestRetry`，记录 waitMs 和脱敏错误 |
| 成功可见 | 模型调用成功后调用 `recordModelRequestSuccess` |
| 失败可见 | 统一包装错误后调用 `recordModelRequestFailure` |
| 取消/超时状态区分 | `TASK_CANCELLED` 记为 `cancelled`，`MODEL_TIMEOUT` 记为 `timeout` |
| 设置页读取 | `settings/request-diagnostics.ts` 返回 `modelRequests` |
| 页面展示 | `RequestDiagnostics.vue` 增加最近模型请求表格 |
| 多语言 | `messages.ts` 增加 `settings.requestDiagnostics.*` |
| 防泄露 | 只返回摘要，不返回 stack、完整路径、密钥、请求体、响应体 |
| 自动验证 | 新增 `verify-opt-014-model-observability.mjs` |

## 3. 关键决定

1. 诊断流水先放内存，不落库。
   - 原因：这是排错面板，不是审计日志；任务中心和业务表才是正式记录。
2. 不返回完整 detail。
   - 原因：detail 可能包含本机路径、密钥、请求头或供应商原始响应。
3. 不把 `OPT-015` 全部标完成。
   - 原因：本地服务状态已经有，模型请求摘要也有了，但 media URL 访问失败、Socket 状态、资源请求流水还没完整接入。
4. 设置入口从“本地服务地址诊断”改成“请求诊断”。
   - 原因：现在它不只是 URL，也包含模型请求。

## 4. 验收标准

1. 模型调用开始后，诊断 store 有一条 `running` 记录。
2. 模型调用成功后，记录变成 `succeeded`，带 duration。
3. 模型调用失败后，记录变成 `failed/timeout/cancelled`，带脱敏失败原因。
4. 临时失败重试时，记录 `retrying`、retryCount、lastRetryWaitMs。
5. 设置页能看到最近模型请求表格。
6. 页面新增可见文案支持中文和英文。
7. 诊断结果不返回 stack、API Key、完整本机路径、请求体和响应体。
8. `verify:core`、`typecheck`、`build` 通过。
