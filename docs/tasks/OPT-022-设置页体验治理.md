# OPT-022 设置页体验治理

## 通俗总结

这次不是新增设置功能，而是让设置页更像用户能理解的入口。

用户打开设置页，应该先看到“生成前必须配置什么”，而不是先看到外观、语言、数据库、Skill、adapter 混在一起。

## 本批范围

1. 设置页顶部从平铺按钮改成分组导航。
2. 把模型服务、Agent、提示词放到最前面。
3. 把文件、外观、语言、业务默认值归到本地工作区。
4. 把用户、关于和版本归到账号与版本。
5. 开发者诊断只在开发环境显示，并继续折叠。
6. 新增文案全部走 i18n。
7. 增加专项 verify，防止设置页重新变回平铺按钮。

## 不做什么

1. 不重写每个设置组件内部表单。
2. 不把开发者诊断开放给普通用户。
3. 不删除数据库、Skill、记忆、供应商 adapter 这些高级能力。
4. 不改设置存储结构和 IPC。

## 具体怎么做

1. 在 `SettingsHome.vue` 增加 `settingsQuickGroups`：
   - `generation`
   - `workspace`
   - `account`
   - `advanced`
2. `generation` 包含：
   - 模型服务
   - Agent 模型配置
   - 提示词管理
3. `workspace` 包含：
   - 文件管理
   - 外观设置
   - 语言设置
   - 其他业务配置
4. `account` 包含：
   - 本地用户配置
   - 关于与版本信息
5. `advanced` 只在 `appInfo.isDev` 时出现。
6. 页面实际区块顺序同步调整为：
   - 模型服务
   - Agent
   - 提示词
   - 文件
   - 外观
   - 语言
   - 业务配置
   - 关于
   - 开发者
   - 用户
   - 退出登录
7. 增加 `settings.guide` 中英文文案。

## 用户能操作什么

1. 点击“生成前必须配置”里的按钮，直接定位模型、Agent、提示词。
2. 点击“本地工作区”里的按钮，定位文件、主题、语言、业务默认值。
3. 点击“账号与版本”，定位本地用户和版本信息。
4. 开发环境下点击“开发诊断”，展开底层诊断区。

## 完成标准

1. 普通用户能先找到模型服务，而不是被外观/语言挡在前面。
2. 开发者能力仍保留，但不和普通配置混在一起。
3. 设置页新增可见文案有中英文。
4. 专项 verify 能检查分组导航、顺序和文案。
