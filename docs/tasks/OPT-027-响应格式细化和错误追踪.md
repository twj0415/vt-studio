# OPT-027 响应格式细化和错误追踪

状态：已完成

## 0. 快速理解

一句话：接口外层仍然是 `{ code, data, msg }`，但失败时 `data` 里会带 `errorCode/msgKey/requestId`。

为什么现在做：后面模型、文件、任务、导出都会失败；如果所有失败只有 `code=400`，页面和日志都很难定位。

做完后有什么用：用户仍看到简单错误提示，开发时可以用 `requestId` 找日志，用 `errorCode` 判断错误类别，用 `msgKey` 做多语言。

这一步不碰什么：不批量重构 renderer 请求封装；页面统一 loading/toast/requestId 展示留给 `OPT-040`。

## 1. 本次做什么

只做：

1. 保持成功 `{ code: 200, data, msg }`。
2. 保持失败顶层 `{ code: 400, data, msg }`。
3. 失败 `data` 固定带：
   - `errorCode`
   - `msgKey`
   - `requestId`
4. `VtError` 保留：
   - `statusCode`
   - `msgKey`
   - `requestId`
   - `detail`
5. `detail/stack/密钥/本机路径` 不返回 renderer，只进日志。
6. 补 `status.xxx` 中英文 i18n 文案，后续 renderer 可优先用 `msgKey`。

不做：

1. 不把顶层失败 code 改成 `70002/60003` 这种细分码。
2. 不把 `msg` 改名成 `message`。
3. 不强行把所有页面改成严格成功/失败联合类型。
4. 不做 renderer 请求封装，那是 `OPT-040`。

## 5. 最后大白话

以后接口失败不是只有“失败”两个字。外面还是 `{ code: 400, data, msg }`，但 `data` 里能知道是哪类错误、用哪个翻译 key、日志里找哪个 requestId。
