# OPT-028 默认字典集中管理

状态：已完成

## 0. 快速理解

一句话：把项目类型、资产类型、模型类型、图片/视频 mode、任务状态、主题、语言、常用分辨率和时长收进一份 shared 字典。

为什么现在做：后面默认资源、模型能力、资产生成、生产和导出都会复用这些 key。如果继续各写各的，筛选、校验、显示和数据库值迟早对不上。

做完后有什么用：新增一个固定 key 时先改 `src/shared/constants/dictionaries.ts`，类型、main 校验和 renderer 选项再从这里派生。

这一步不碰什么：不重构所有页面文案，不重做业务状态分层，不改数据库已有英文 key，不把 `succeeded` 改成 `success`。

## 2. 关键决定

1. 正式完成态使用 `succeeded`，不使用 `success`。
   - 原因：当前任务、资产、生产、剧本提取都已经用 `succeeded`，改成 `success` 会破坏已有数据和页面状态。
2. 资产类型沿用当前已落库 key：`role/scene/tool/clip/audio`。
   - 原因：当前资产中心、角景音频、生产工作台都已经围绕这些 key 工作，不为了字面英文重命名破坏链路。
3. `waiting` 只进入任务状态字典和展示文案，不改变当前任务 service 的创建逻辑。
   - 原因：当前任务创建后直接 `running`。真正等待队列、并发锁和排队规则属于 `OPT-013/OPT-038`。
4. 这次只做字典集中和最小接线，不全量清理 renderer 中文硬编码。
   - 原因：可见文案全量治理已经排到 `OPT-047`，混在本任务会扩大范围。
