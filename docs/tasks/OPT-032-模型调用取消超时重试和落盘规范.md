# OPT-032 模型调用取消、超时、重试和落盘规范

状态：已完成

## 0. 快速理解

一句话：让模型调用从“发出去等结果”升级成“能追踪、能超时、能识别取消、失败能说明原因、业务落盘不被迟到结果覆盖”。

为什么现在做：图片、视频、TTS 和后续 ComfyUI 都是长任务。没有运行规则，用户点取消后模型可能还会返回结果，代码又把文件写成成功；或者第三方接口卡住，任务中心永远看不懂哪里失败。

做完后有什么用：每次模型调用都有 requestId；调用有超时上限；网络类临时错误可有限重试；业务任务可以把 taskId 传进模型层；取消后的迟到结果不会再写成成功。

这一步不碰什么：不做 ComfyUI workflow manifest；不新增任务中心通用取消按钮；不重写所有业务落盘表结构；不承诺所有第三方 SDK 都能被物理中断。第三方不支持 AbortSignal 时，只保证 VT Studio 不再把取消后的迟到结果写成功。

## 1. 本次做什么

1. 模型调用网关补运行选项：
   - `timeoutMs`
   - `retry`
   - `taskId`
   - `isCancelled`
2. 超时规则：
   - 默认读取“其他业务配置”的 `requestTimeoutMs`
   - 超时返回统一模型错误，并带 requestId
   - 超时后的迟到结果不再进入业务成功写入
3. 重试规则：
   - 只对网络类临时错误重试
   - 不重试参数错误、未配置、API Key 缺失、权限错误、取消错误
   - 重试次数有限，日志记录第几次失败和下一次等待
4. 取消规则：
   - 模型调用前检查 task 是否已取消
   - 模型返回后再次检查 task 或业务对象是否已取消
   - 已取消则抛 `TASK_CANCELLED`
   - 外层业务任务负责最终 `cancelled/failed/succeeded` 状态
5. 媒体入参隔离：
   - `task` 是 VT Studio 内部参数，不传给供应商 adapter
   - adapter 只拿 prompt、referenceList、mode、size、duration 等业务参数
6. 媒体结果校验增强：
   - URL 只允许 http/https
   - 下载使用超时
   - `content-length` 和实际大小都检查
   - MIME 必须匹配 image/video/audio
   - reference base64 先做大小预算，避免超大输入直接打爆内存
7. 资产图片生成接入：
   - `asset_media` 记录 `task_id`
   - 点击取消时业务媒体状态先变 `cancelled`
   - 模型层通过 `mediaId` 检查取消，迟到结果不再写文件
8. 生产图片/视频生成接入：
   - 分镜图片、衍生资产图片、视频候选把外层 taskId 传入模型层
   - 生成返回后仍按业务表状态二次确认
9. 专项验证：
   - 检查网关有超时、重试、取消能力
   - 检查媒体调用不会把 `task` 传给 adapter
   - 检查资产媒体记录有 `task_id`
   - 检查生产生成把 taskId 传入模型层

## 2. 关键决定

1. 不把所有模型调用默认强制物理中断。
   - 原因：不同 SDK 和参考项目 adapter 对 AbortSignal 支持不一致，硬加会制造假安全。
2. 当前先做“业务上不再误写成功”。
   - 原因：这是用户能直接感知的关键问题，也是后续任务中心通用取消入口的基础。
3. 图片和音频可对网络类临时错误做一次有限重试，视频默认更保守。
   - 原因：视频生成成本更高、耗时更长，默认重复生成风险大。
4. 落盘不新建第二套全局媒体表。
   - 原因：当前资产、生产已经有各自明确的业务落盘点；本任务先把写入前后的状态检查补齐，完整文件生命周期继续归 `OPT-036`。
5. requestId 进入日志和错误，不把完整 stack、路径、密钥返回页面。
   - 原因：多语言和安全边界已经由 `OPT-027/CORE-005` 固定。

## 3. 要做什么功能：怎么做

| 要做什么 | 怎么做 |
|---|---|
| 模型调用超时 | `runModelCall` 使用 `Promise.race` 包一层超时，默认读业务配置 |
| 临时错误重试 | `runModelCall` 判断网络/429/5xx/ECONNRESET/ETIMEDOUT 等，再按有限次数重试 |
| 调用前检查取消 | `runModelCall` 执行 runner 前检查 `taskId` 和 `isCancelled` |
| 调用后检查取消 | runner 成功返回后再检查一次，取消时抛 `TASK_CANCELLED` |
| requestId 贯穿 | 开始、重试、成功、失败日志都带 requestId/taskId |
| 内部 task 不给 adapter | 媒体调用复制入参并删除 `task`，再传给 `runtime.imageRequest/videoRequest/ttsRequest` |
| URL 下载可控 | 媒体 URL 下载只允许 http/https，下载前看 content-length，下载后看实际大小和 MIME |
| 参考图预算 | referenceList 里的 base64 按 image/video/audio 最大体积校验 |
| 资产取消不误写 | `asset_media.task_id` 记录外层任务；取消后模型返回也先检查业务状态 |
| 生产任务透传 | 分镜图、衍生资产图、视频候选生成把外层 taskId 放进模型调用 task 选项 |
| 验证脚本 | 新增 `verify-opt-032-model-runtime.mjs` 并接入 `verify:core` |

## 4. 验收标准

1. 模型调用日志能看到 requestId、taskId、协议、耗时。
2. 模型调用超时会失败，不会一直挂住。
3. 临时网络错误最多有限重试，不会无限重试。
4. 取消后的模型迟到结果不会把业务对象改成成功。
5. 供应商 adapter 收不到 VT Studio 内部 `task` 函数。
6. 超大 URL 结果、错误 MIME、非法 URL 会被拒绝。
7. `asset_media` 能追溯到任务中心 taskId。
8. `verify:core`、`typecheck`、`build` 通过。
