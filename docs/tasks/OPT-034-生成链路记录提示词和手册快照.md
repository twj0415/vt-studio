# OPT-034 生成链路记录提示词和手册快照

## 通俗总结

这一步是给生成结果留“案底”。

用户看到一张资产图、一张分镜图、一条视频提示词或一个视频候选时，后面必须能查到：当时用的是哪个模型、哪个 requestId、哪个最终 prompt、哪个提示词模板、哪版视觉手册和导演手册、引用了哪些素材。

否则后期结果不满意、模型失败、手册改版、导出复现时，只能靠猜。

## 参考项目怎么做

| 参考位置 | 结论 |
|---|---|
| `Toonflow-app-master/src/routes/assetsGenerate/*` | 资产图和资产提示词生成会把资产、模型、参考图、项目配置组合成最终 prompt |
| `Toonflow-app-master/src/routes/taskRecord.ts` | 生成类动作会进任务记录，失败原因和任务状态可追踪 |
| `Toonflow-app-master/src/routes/videoGenerate/*` | 视频提示词、参考素材、视频 mode 是视频生成的重要上下文 |
| `resources/default-data/skills/art_skills/*` | 视觉/导演 Skill 内容会影响生成结果，因此生成记录必须知道用的是哪版内容 |

参考项目更偏接口任务记录；VT Studio 是本地桌面软件，还需要把可复现快照落到本地数据库和页面详情里。

## 要做什么

1. 建立统一生成快照 helper：
   - source：是哪条链路生成的。
   - model：使用的模型 ID。
   - modelMode：视频 mode 或模型模式。
   - requestId：模型请求追踪 ID。
   - taskId：任务中心 ID。
   - userPrompt：用户/业务原始提示词。
   - finalPrompt：最终交给模型的提示词。
   - promptTemplate：提示词模板内容、hash、来源。
   - manuals：视觉手册、导演手册内容、hash、路径、更新时间。
   - references：参考图、分镜、资产、视频候选等引用关系。
2. 模型调用允许外层透传 requestId：
   - 业务层先创建 requestId。
   - 快照和模型网关使用同一个 requestId。
   - adapter 入参不收到这个内部字段。
3. 资产图生成写快照：
   - 写入 `asset_media.metadata.generationSnapshot`。
   - 记录资产类型、父资产、用途、视图模式、画质、参考图数量。
4. 生产分镜图写快照：
   - 写入 `production_storyboards.generation_metadata`。
   - 记录分镜 ID、剧本 ID、关联资产、画质、比例、手册内容。
5. 生产衍生资产图写快照：
   - 写入 `asset_media.metadata.generationSnapshot`。
   - 记录父资产、参考父图、视觉/导演手册。
6. 视频提示词写快照：
   - 写入 `production_video_tracks.generation_metadata`。
   - 记录使用的视频 prompt 模板、手册、分镜 ID、系统提示词。
7. 视频候选写快照：
   - 写入 `production_videos.generation_metadata`。
   - 记录 prompt、mode、参考素材、时长、分辨率、是否带音频。
8. 页面提供查看入口：
   - 资产中心能查看当前资产图的生成记录。
   - 生产工作台能查看分镜图、视频轨道、已选视频候选的生成记录。

## 具体怎么做

1. 新增 `src/main/services/generation/snapshot.ts`：
   - `createGenerationSnapshot()` 统一生成快照结构。
   - `createPromptTemplateSnapshot()` 记录模板内容和 hash。
2. 修改 `src/main/services/project/manual-prompt.ts`：
   - 增加 `toManualPromptContentSnapshot()`。
   - 快照里保留手册内容，不只保留 hash。
3. 修改模型层：
   - `src/main/services/model/types.ts` 的文本、图片、视频、TTS 入参增加 `requestId`。
   - `text.ts`、`media.ts` 透传 requestId 到模型网关。
   - `media.ts` 传给 adapter 前剥离 requestId。
4. 修改资产服务：
   - 资产图生成先创建 requestId。
   - `createGenerationMetadata()` 只创建一次 generationSnapshot，不重复覆盖。
   - 生成前写入 metadata，成功后保留同一份快照。
5. 修改生产服务：
   - 给分镜、视频轨道、视频候选表增加 `generation_metadata`。
   - mapper 返回 `generationMetadata` 给 renderer。
   - 分镜图、衍生资产图、视频提示词、视频候选生成都写快照。
6. 修改前端：
   - 资产中心复用现有详情弹窗查看生成记录。
   - 生产节点复用 `showDetail` 查看分镜/轨道/已选视频生成记录。
   - 新增文案必须进入 i18n。
7. 新增 verify：
   - `scripts/verify-opt-034-generation-snapshot.mjs`。
   - 接入 `verify:production`。

## 不做什么

1. 不做上游变更后的下游失效规则；这个归 `OPT-054`。
2. 不做孤儿文件、md5、尺寸、duration 生命周期治理；这个归 `OPT-036`。
3. 不做导出历史；这个归 `OPT-056`。
4. 不把快照做成复杂可视化页面；本任务先保证能查到完整结构。

## 完成标准

1. 同一次生成的快照 requestId 和模型网关 requestId 一致。
2. 资产图、分镜图、衍生资产图、视频提示词、视频候选都有生成快照。
3. 快照包含最终 prompt、模型、任务、手册内容/hash、引用关系。
4. 页面能查看生成记录，不需要去翻数据库。
5. 生成快照不包含 API Key。
6. verify、typecheck、build 通过。
