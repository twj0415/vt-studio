# OPT-035 密钥存储、脱敏、备份和导出规范

状态：已完成

## 0. 快速理解

一句话：API Key、token、secret 可以被 main 侧用于调用模型，但不能被页面、日志、诊断、任务失败原因、项目导出包随便看到。

为什么现在做：模型调用已经统一，后面要接 ComfyUI、图片、视频、TTS。如果密钥边界不先收住，后面每加一个协议都会多一个泄露点。

做完后有什么用：用户能配置和测试模型，但编辑页面不会回显完整密钥；日志和诊断不会出现明文 key；数据库完整备份会明确提示包含密钥；业务导出不带全局供应商密钥。

这一步不碰什么：不做系统钥匙串，不做 SQLite 全库加密，不重做账号密码体系，不实现项目迁移包，只给现有链路加安全边界。

## 1. 本次做什么

1. 建立统一敏感字段工具：
   - 判断 `apiKey/token/secret/password/authorization` 等敏感 key。
   - 脱敏字符串里的 key、Bearer token、URL query。
   - 生成“已配置但不展示”的展示值。
2. 普通模型服务配置：
   - list/resource 返回给 renderer 时不带明文 `apiKey`。
   - 返回 `apiKeyConfigured` 和 `apiKeyMasked`。
   - 编辑时 API Key 留空表示不修改旧密钥。
   - 新建非本地 workflow 时仍要求填写 API Key。
3. 高级 vendor 配置：
   - list 返回给 renderer 时，password/敏感输入不带明文。
   - 返回每个敏感输入的 configured/masked 状态。
   - 保存时敏感字段留空表示不修改旧值。
   - 新建或未配置必填敏感字段时仍要求填写。
4. 日志和诊断：
   - logger 使用统一脱敏，不只按对象 key 脱敏，也处理 message/detail 中的明文。
   - 模型请求诊断复用统一脱敏。
5. 数据库备份：
   - 备份列表和导出结果标记 `containsSecrets=true`。
   - 数据库管理页明确说明完整 SQLite 备份包含模型密钥、登录 token 和本地配置。
   - 自动备份、导入、清表、清空全部继续保持原能力，但提示语义明确。
6. 导出边界：
   - 当前 P10 导出只写时间线、素材路径和导出摘要，不写 `modelConnections/model_vendors/app_settings`。
   - 本轮增加验证脚本，防止导出 JSON、诊断返回、日志工具重新泄露常见测试密钥。

## 2. 要做什么功能：怎么做

| 要做什么 | 怎么做 |
|---|---|
| 统一脱敏 | 新增 shared 安全工具，main 的 logger、模型诊断、设置服务复用 |
| 普通模型页面不回显 key | `getApiConnectionList/getResourceConfig/saveApiConnection` 返回 public connection，`apiKey=''`，另带 configured/masked |
| 普通模型保存不覆盖旧 key | `normalizeDraft` 遇到编辑且 key 留空时沿用 previous.apiKey |
| 高级 vendor 页面不回显 key | `manifestToListItem` 返回 public inputValues，敏感字段为空，另带 configured/masked |
| 高级 vendor 保存不覆盖旧 key | `saveVendorInputs` 对敏感空值沿用旧值 |
| 必填校验不误伤旧 key | renderer 按 configured 状态判断空敏感字段是否可接受 |
| 数据库备份提示含密钥 | `DatabaseBackupItem/ExportResult` 增加 `containsSecrets`，页面提示和弹窗说明 |
| 日志脱敏统一 | logger 用统一工具递归脱敏对象和文本 |
| 自动验证 | 新增 `verify-opt-035-secret-boundary.mjs`，覆盖 public connection/vendor、logger、数据库备份元信息和导出代码不含全局密钥表 |

## 3. 关键决定

1. 第一版仍把密钥保存在 SQLite/app settings。
   - 原因：项目已用 SQLite 做本地配置；直接引入系统钥匙串会牵动迁移、备份、恢复、跨机器导入。
   - 边界：这是“本机完整备份包含密钥”，不是“项目迁移包包含密钥”。
2. renderer 永远不需要拿明文 API Key。
   - 原因：模型调用、测试和 vendor runtime 都在 main。
3. 编辑密钥采用“留空不修改”。
   - 原因：既能保护明文，又不让用户每次编辑名称或模型列表都重新填 key。
4. 完整数据库备份允许包含密钥，但必须明显提示。
   - 原因：完整备份用于本机恢复；去掉密钥会让恢复后的模型不可用。
5. 项目导出包默认不包含全局密钥。
   - 原因：项目包用于迁移/分享，不应该带走用户供应商账号能力。

## 4. 验收标准

1. 普通模型服务列表返回给 renderer 的 `apiKey` 为空，且有 `apiKeyConfigured=true`。
2. 编辑普通模型服务时不填 API Key，保存后旧 key 仍可用于测试。
3. 高级 vendor 的 password/敏感输入返回页面时为空，且有 configured/masked 状态。
4. 高级 vendor 编辑非敏感字段时，敏感字段留空不会清掉旧 key。
5. logger、模型请求诊断、任务失败原因不出现测试密钥明文。
6. 数据库备份列表和导出结果明确标记包含密钥。
7. P10 导出代码不写 `modelConnections.v1`、`model_vendors`、`app_settings` 这类全局密钥配置。
8. `verify:settings`、`verify:core`、`typecheck`、`build` 通过。

## 8. 最后大白话

以后页面只知道“这个 key 已经配过”，不会把完整 key 拿到前端；你要改 key 就重新输入，不改就留空。完整数据库备份是本机恢复用的，里面可能有密钥，所以必须明确提醒；项目导出和剪映导出这种业务包不应该带走全局 API Key。
