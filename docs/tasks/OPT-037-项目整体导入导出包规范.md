# OPT-037 项目整体导入导出包规范

## 通俗总结

这次做的是“项目搬家包”。

以前只能导出剧本 zip、剪映草稿、数据库备份；这些都不是完整项目迁移。现在一个项目可以导出成 `.vtproject` 目录包，里面带项目业务数据、项目素材、生成结果、视觉手册快照、导演手册快照和项目记忆。

第一版不做压缩 zip，而是目录包。原因很简单：当前项目没有 zip 依赖，目录包更透明、更容易排查，也不会为了“单文件”引入新的不稳定依赖。

## 本批范围

要做什么：

1. 定义 `.vtproject` 项目包目录结构。
2. 项目页支持导出当前项目迁移包。
3. 项目页支持按路径导入 `.vtproject` 项目包。
4. 导入时创建新项目，不覆盖旧项目。
5. 导入时重映射这些 ID：
   - project id
   - script id
   - asset id
   - asset media id
   - storyboard id
   - video track id
   - video id
   - image flow id
   - manual id
6. 导入时把项目相对素材路径从旧项目 ID 改成新项目 ID。
7. 导入时复制项目文件：
   - `source/`
   - `assets/`
   - `generated/`
   - `production/`
8. 导出时带手册快照：
   - `manual_snapshots/visual/`
   - `manual_snapshots/director/`
9. 生成 `manifest.json`、`project.json`、`database.json`。
10. 默认不导出 API Key、登录态、任务记录、缓存、临时文件。
11. 导入导出前检查运行中任务和业务锁。
12. 新增可见文案走 i18n。
13. 新增专项 verify，并挂到 `verify:project`。

## 不做什么

1. 不做 zip 单文件压缩包。
2. 不导出全局供应商密钥、请求头、API Key。
3. 不导出登录态和用户会话。
4. 不导出任务运行记录。
5. 不把项目包功能混进剪映导出中心。
6. 不直接复制整库。
7. 不覆盖已有项目。

## 项目包结构

```txt
xxx.vtproject/
  manifest.json
  project.json
  database.json
  source/
  assets/
  generated/
  production/
  manual_snapshots/
    visual/
    director/
  prompt_snapshots/
    manifest.json
```

说明：

1. `manifest.json` 记录包版本、项目名、导出时间、表数量、文件数量和明确排除项。
2. `project.json` 记录项目包格式和目录说明。
3. `database.json` 只保存项目相关业务表，不保存全局配置和密钥。
4. `prompt_snapshots/manifest.json` 只说明提示词快照边界；生成链路里的真实提示词快照继续留在业务数据的 `generation_metadata/metadata` 中。

## 具体怎么做

1. `src/shared/types/project.ts`
   - 增加项目包导出、导入、打开目录的 payload/result 类型。
   - 增加项目包 summary 类型。
2. `src/main/services/project.ts`
   - 增加项目包常量。
   - 读取项目相关表：
     - `projects`
     - `visual_manuals`
     - `director_manuals`
     - `source_chapters`
     - `agent_work_data`
     - `scripts`
     - `assets`
     - `asset_media`
     - `asset_audio_links`
     - `script_asset_links`
     - `production_workspaces`
     - `production_video_tracks`
     - `production_storyboards`
     - `production_storyboard_asset_links`
     - `production_image_flows`
     - `production_videos`
     - `memories`
   - 导出前检查项目级业务锁。
   - 导入前检查全局业务锁。
   - 导出到 `exports/project-packages/*.vtproject`。
   - 导入时用事务写入新项目。
   - 导入失败时回滚数据库，并清理已经创建的新项目目录。
   - 当前环境没有原模型时，映射到可用默认模型并返回 warning。
3. `src/main/ipc/project.ts`
   - 增加 `project:package:export`。
   - 增加 `project:package:import`。
   - 增加 `project:package:open-directory`。
4. `src/shared/contracts/preload.ts`、`src/preload/index.ts`
   - 暴露 `window.vtStudio.project.exportPackage`。
   - 暴露 `window.vtStudio.project.importPackage`。
   - 暴露 `window.vtStudio.project.openPackageDirectory`。
5. `src/renderer/src/features/project/ProjectHome.vue`
   - 项目卡片增加“导出项目包”。
   - 页面顶部增加“导入项目包”。
   - 导出成功后提示包路径，并可打开目录。
   - 导入弹窗输入 `.vtproject` 目录路径。
6. `src/renderer/src/i18n/messages.ts`
   - 增加项目包相关中英文文案。
7. `scripts/verify-opt-037-project-package.mjs`
   - 检查类型、service、IPC、preload、UI、i18n 和文档状态。
8. `scripts/verify.mjs`
   - 将专项 verify 挂到 `verify:project`。

## 用户能操作什么

1. 在项目卡片上导出项目包。
2. 导出成功后打开 `.vtproject` 包目录。
3. 在项目页顶部导入 `.vtproject` 项目包。
4. 导入后在项目列表看到新项目。
5. 如果原模型不可用，会看到模型映射 warning。

## 完成标准

1. 项目能导出 `.vtproject` 目录包。
2. 项目包包含 `manifest.json`、`project.json`、`database.json`。
3. 项目包包含项目素材和手册快照。
4. 导入会创建新项目，不覆盖旧项目。
5. 导入后项目相对路径指向新项目目录。
6. 导入导出不会带 API Key、登录态、任务记录。
7. 页面不直接访问 Node、SQLite、文件系统。
8. 新增文案有中英文。
9. `verify:project` 包含 OPT-037 专项检查。
