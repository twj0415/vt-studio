# OPT-038 任务并发和业务锁统一

状态：已完成

## 0. 快速理解

一句话：删除项目、导入数据库、清表、清空全部前，不再只看 `tasks.running`，而是统一检查任务记录和业务对象运行态。

为什么现在做：生成图片、生成视频、事件分析、资产提取都可能已经把业务对象标成 `running`。如果这时删除项目或清空数据库，后台任务结束后会找不到对象，或者把结果写到已经不存在的数据上。

做完后有什么用：危险操作前能明确提示“哪个任务/对象正在占用”，后续新增长任务只要业务状态登记到锁 service，就能自动挡住全局危险操作。

这一步不碰什么：不重写所有模块内的单对象锁；原文、剧本、资产、生产里已有的“正在生成不能编辑/删除”先保留。更细的取消、超时、迟到结果覆盖继续归 `OPT-032`。

## 3. 具体怎么做

1. 危险操作开始前：
   - 调 `assertNoBusinessLocks({ projectId?, action })`
   - 有锁直接抛 `TASK_STATUS_CONFLICT`
   - 错误文案包含任务/对象类型和数量
2. 项目级危险操作：
   - 传 `projectId`
   - 只检查当前项目范围内的任务和业务对象
3. 全局危险操作：
   - 不传 `projectId`
   - 检查全库任务和业务对象
4. 页面展示：
   - 继续显示 `runningTaskCount` 兼容旧页面和旧脚本
   - 新增 `runningLockCount/runningLocks` 给用户看真实占用来源
5. 后续新增长任务：
   - 如果有新的业务表和运行态字段，必须补进 `task/locks.ts`
   - 不能在项目删除、数据库管理里再写一套局部 running SQL
