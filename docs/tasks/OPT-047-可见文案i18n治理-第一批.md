# OPT-047 可见文案 i18n 治理 - 第一批

状态：已完成

## 0. 快速理解

一句话：先把最基础、最容易影响全局观感的硬编码文案清掉：应用初始化、路由标题、菜单标题/描述、store 里的用户可见错误。

为什么分批做：renderer 里硬编码文案很多，设置页、业务页、弹窗、表格和 toast 全部一次性改风险太高。第一批先做入口和全局状态，后续再按页面拆。

这一步不碰什么：不迁移 `ModelServiceConfig.vue`、`VendorConfig.vue`、`SkillManagement.vue` 等大设置页，也不迁移资产、生产、导出页面的大量表单文案。它们进入后续批次。

## 1. 扫描结论

当前第一批明确发现：

1. `App.vue` 初始化 loading/error 文案硬编码中文。
2. `router/index.ts` 的 `meta.title` 是中文。
3. `router/menu.ts` 的菜单标题和描述是中文数据。
4. `stores/auth.ts` 里登录失败、会话恢复失败、用户配置失败等 fallback 是中文。
5. `stores/app.ts` 里初始化失败 fallback 是中文。

更大的硬编码集中在设置页和业务页，后续分批处理，不在这里假装全量完成。

## 2. 要做什么功能：怎么做

| 要做什么 | 怎么做 |
|---|---|
| 应用初始化文案 | `App.vue` 引入 `useI18n()`，loading/error 走 `app.bootstrapLoading/app.bootstrapFailed` |
| 路由标题 | `router/index.ts` 改为 `meta.titleKey`，不再写中文 title |
| 菜单标题和描述 | `MenuModule` 改为 `titleKey/descriptionKey`，布局里用 `t()` 转成可见文案 |
| store 错误 fallback | 新增 renderer 翻译工具，`auth/app` store 用 key 获取 fallback 文案 |
| 中英文语言包 | `messages.ts` 补 `app/auth/routeDescription` 中英文文案 |
| 防回退 | 新增 verify，确保本批文件不再有中文硬编码 |

## 4. 验收标准

1. 本批目标文件不再出现中文硬编码。
2. 应用初始化 loading/error 能随语言切换。
3. 菜单标题和路由标题仍正常显示。
4. auth/app store 的 fallback 错误走 i18n。
5. typecheck、settings verify、docs verify、build 通过。
