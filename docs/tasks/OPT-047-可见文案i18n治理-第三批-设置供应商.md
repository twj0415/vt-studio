# OPT-047 可见文案 i18n 治理 - 第三批：设置供应商

状态：已完成

## 0. 快速理解

一句话：这次只处理设置页里的 `VendorConfig.vue`，把底层供应商配置页能看到的中文文案全部改成 i18n key。

为什么要做它：这个页面是高级供应商、模型、adapter、测试入口的底层管理页。如果这里还写死中文，语言设置就会出现“外面能切语言、进高级配置又变中文”的问题。

这一步不碰什么：不改供应商保存逻辑、不改密钥脱敏、不改 adapter 安全沙盒、不改模型测试协议、不重做 UI。

## 1. 扫描结论

`VendorConfig.vue` 的硬编码主要集中在这些地方：

1. 模型类型：文本、图片、视频、TTS。
2. 图片和视频模式：文生图、单图参考、多图参考、首尾帧、视频加图片参考等。
3. 供应商列表状态：已启用、未启用、模型服务生成、内置、自定义、可用、待处理。
4. 连接参数：保存参数、密钥已保存提示、动态输入空状态、Base URL 填写提示。
5. 模型列表：添加模型、测试模型、编辑模型、删除模型、空模型提示。
6. 模型弹窗：标题、表单 label、placeholder、视频模式选择、音频开关、音色。
7. 测试弹窗：默认 prompt、测试标题、开始测试、结果、耗时、图片/视频测试成功提示。
8. 高级 adapter：新增自定义供应商、编辑 adapter、删除供应商、adapter 状态、最后错误、代码输入提示。
9. 删除确认弹窗：删除模型、删除供应商、确认按钮、取消按钮。
10. toast 和校验提示：必填、模型参数不完整、TTS 音色格式、只读投影不能改等。

## 2. 要做什么功能：怎么做

| 要做什么 | 怎么做 |
|---|---|
| 组件接入 i18n | `VendorConfig.vue` 引入 `useI18n()`，所有可见静态文案走 `t('settings.vendorConfig.xxx')` |
| 模型类型和能力标签 | `MODEL_TYPE_OPTIONS` 改成 `labelKey`，能力展示用 `getCapabilityLabel()` 读取语言包 |
| 图片/视频模式标签 | 图片模式、视频 mode preset 不再写死中文，统一通过 `getImageModeLabel()`、`getVideoModeLabel()` |
| 供应商状态展示 | 已启用、未启用、模型服务生成、内置、自定义、adapter 状态等前端自己能判断的文案走语言包 |
| 动态错误和接口返回 | `response.msg`、`selectedVendor.lastError`、自定义 adapter 运行错误保留原样展示，不在前端乱翻译 |
| 表单、按钮、placeholder | 模型弹窗、测试弹窗、adapter 弹窗所有 label、placeholder、confirm 按钮走语言包 |
| toast 和 Dialog | `MessagePlugin`、`DialogPlugin.confirm` 里的静态文案全部走语言包 |
| 中英文语言包 | `messages.ts` 新增 `settings.vendorConfig.*`，`zh-CN` 和 `en` 同步补齐 |
| 防回退 | 新增专项 verify，检查组件不再出现中文硬编码，并确认关键 i18n key 存在 |
| 旧校验更新 | 旧 verify 不再查页面中文，改查 `settings.vendorConfig.*` key |

## 4. 验收标准

1. `VendorConfig.vue` 不再出现中文硬编码。
2. 供应商配置页标题、按钮、tag、空状态、表单、toast、弹窗、测试结果都走 i18n。
3. 切换语言后，供应商配置页静态文案能跟随语言包变化。
4. 接口 `response.msg`、adapter 运行错误、最后错误继续原样展示，不在前端二次乱翻译。
5. 密钥留空不覆盖旧值、只读投影不能编辑、adapter 安全边界这些业务逻辑不变。
6. 专项 verify、typecheck、settings verify、docs verify、build 通过。
