# OPT-047 可见文案 i18n 治理 - 第二批：设置模型服务

状态：已完成

## 0. 快速理解

一句话：这次只处理设置页里的 `ModelServiceConfig.vue`，把模型服务配置页能看到的中文文案全部改成 i18n key。

为什么先做它：模型服务是文本、图片、视频、TTS 调用的基础入口，用户最先会看这里。如果这里的按钮、提示、弹窗、测试结果还写死中文，后面语言设置就不是真正可用。

这一步不碰什么：不改 `VendorConfig.vue`、`SkillManagement.vue`、模型调用逻辑、数据库字段、供应商 adapter，也不顺手重做 UI 样式。

## 1. 扫描结论

`ModelServiceConfig.vue` 里硬编码主要集中在这些地方：

1. 能力标签：文本、图片、视频、语音。
2. 默认测试 prompt：文本、图片、视频各有默认提示词。
3. 测试结果格式：测试文件、无内容提示、思考内容、耗时。
4. 表单校验 toast：服务名称、API Key、ComfyUI Endpoint、Workflow Manifest、模型选择。
5. 操作反馈 toast：创建、保存、删除、默认模型更新、测试成功。
6. 删除确认弹窗：标题、正文、删除/取消按钮。
7. 页面标题、按钮、卡片标题、空状态、tooltip、dialog 标题、表单 label、placeholder、hint。

## 2. 要做什么功能：怎么做

| 要做什么 | 怎么做 |
|---|---|
| 组件接入 i18n | `ModelServiceConfig.vue` 引入 `useI18n()`，所有可见文案用 `t('settings.modelService.xxx')` |
| 能力标签 | `CAPABILITY_OPTIONS` 改成 `labelKey`，展示和测试结果都走 `getCapabilityLabel()` |
| 默认测试 prompt | 文本、图片、视频默认 prompt 放进语言包，运行时用 `t()` 获取 |
| 表单校验和 toast | `MessagePlugin.warning/success/error` 的 fallback 全部用 i18n，接口返回的 `response.msg` 保留后端原文 |
| 删除弹窗 | `DialogPlugin.confirm` 的 header/body/confirm/cancel 全部用 i18n，正文用 `{name}` 参数 |
| 模板和属性文案 | `title`、`description`、`label`、`placeholder`、`header`、`confirm-btn` 改为绑定 i18n |
| 中英文语言包 | `messages.ts` 新增 `settings.modelService.*`，中英文都补齐 |
| 防回退 | 新增 verify，检查该组件不再出现中文硬编码，并确认关键 i18n key 存在 |
