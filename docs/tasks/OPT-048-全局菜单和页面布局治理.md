# OPT-048 全局菜单和页面布局治理

状态：已完成第一批

## 0. 快速理解

一句话：先把全局工作台骨架收稳，让用户知道自己在哪、当前项目是什么、主内容从哪里开始。

为什么现在做：页面能跑，但左侧和顶部项目菜单重复，设置页 Agent 入口还存在组件未导入问题，继续堆页面会越来越乱。

做完后有什么用：后续再改项目页、原文页、剧本页、工作台时，有统一骨架，不会每页长一套。

这一步不碰什么：不重做所有业务页，不重做生产工作台细节，不调整数据库/模型/任务逻辑；页面逐项体验整改放到 `OPT-049/050/051`。

## 1. 参考项目怎么做

| 范围 | 结论 |
|---|---|
| Toonflow 菜单 | 参考项目按 Web 管理后台方式组织菜单，业务入口多，但没有适配 VT Studio 当前 Electron 桌面壳 |
| 当前 VT Studio | 左侧有全局菜单和项目菜单，顶部又重复一组项目菜单；用户会误以为两个区域职责不同 |
| 当前设置页 | 设置项已很多，普通配置和开发者配置有折叠，但缺少快速定位，且 `AgentConfig` 未导入 |

参考项目能借鉴：

1. 项目内模块要能快速切换。
2. 设置类页面要把普通用户配置和开发者配置分开。
3. 任务、项目、生成链路入口必须固定，不能隐藏在深层。

VT Studio 不能照搬：

1. 当前是桌面端工作台，不能把导航做成网页后台的多层菜单。
2. 不能继续让左侧和顶部重复同一组模块入口。
3. 设置页不能按技术文件堆叠，必须给用户快速定位入口。

源码未找到：

1. 参考项目没有找到和 VT Studio 当前 Electron 标题栏、左侧栏、主滚动层完全一致的布局约束。

## 2. 本次做什么

1. 修复设置页 `AgentConfig` 未导入的问题。
2. 统一全局工作台骨架：
   - 左侧保留全局入口和项目内模块入口。
   - 顶部只负责当前页面标题、当前项目状态、项目列表和设置快捷入口。
   - 移除顶部重复项目菜单，避免双导航混乱。
3. 主内容区补可访问性入口：
   - 增加 skip link。
   - 主内容区有固定 id 和 `tabindex="-1"`。
4. 顶部项目信息更清楚：
   - “框架预览”改成“当前项目”。
   - 当前项目旁提供“项目列表”和“设置”按钮。
5. 设置页增加快速定位导航。
6. 新增 verify，防止这些入口和 i18n 回退。

## 7. 偏差

和 Toonflow 不同的地方：VT Studio 顶部不再重复项目模块菜单，只展示项目上下文和快捷操作。

原因：桌面端左侧已经有项目模块入口，顶部再放一组会让用户不知道哪组才是主导航。

是否写入 04：不需要；这是 UI 壳层治理，不改变业务语义。

5. 设置页 Agent 配置真实渲染，不再缺导入。

7. 新增文案走 i18n，中文/英文都补齐。
8. 新增普通样式不写入全局 SCSS。
