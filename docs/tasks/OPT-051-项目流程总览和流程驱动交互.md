# OPT-051 项目流程总览和流程驱动交互

状态：已完成；四批闭环：流程总览、业务页下一步提示、真实统计、任务中心失败原因联动

一句话：打开项目后先看到“这条视频该怎么做”，不要让用户靠菜单猜下一步。

## 第一批只做什么

1. 新增项目流程总览页，作为项目打开后的默认页面。
2. 在项目内菜单第一项增加“流程总览”。
3. 把导出入口补进项目内菜单，因为完整流程最后一步必须能跳到导出。
4. 流程总览按真实生产顺序展示：
   - 基础配置
   - 原文导入
   - 剧本 Agent
   - 剧本确认
   - 提取资产
   - 资产生成/替换
   - 角景音频绑定
   - 分镜生产
   - 图片检查
   - 视频生成
   - 导出剪映草稿
5. 每一步都显示：状态、关键数量、缺什么、跳转按钮。
6. 小说项目显示原文和剧本 Agent；剧本项目把这两步标为跳过。
7. 所有可见文案写进 i18n，中英文都要有。

## 第一批不做什么

1. 不新增数据库表。
2. 不新增统计接口。
3. 不在总览页伪造章节数、剧本数、资产数、分镜数、视频数。
4. 不改生产画布，不把资产提取、图片检查、导出强塞进画布。
5. 不改每个业务页顶部的“下一步提示”，这放第二批。

## 要做什么功能 / 怎么做

| 功能 | 怎么做 |
| --- | --- |
| 打开项目默认进流程总览 | `project.open` 返回 `project-overview`，前端按返回路由跳转 |
| 流程总览页面 | 新建 `ProjectOverviewHome.vue`，只读 `appStore.currentProject`，不直接访问 SQLite 或文件系统 |
| 项目内菜单 | `router/menu.ts` 第一项加流程总览，最后补导出 |
| 路由 | `router/index.ts` 增加 `project-overview`，必须 `requiresProject: true` |
| 小说/剧本差异 | `currentProject.sourceType !== novel` 时，原文和剧本 Agent 标为跳过 |
| 状态展示 | 第一批只用可靠状态：基础配置已完成，后续未开始/需处理/跳过 |
| 关键数量 | 先明确“待接统计接口”，不显示假数字 |
| 跳转按钮 | 每一步跳到真实业务页面：项目、原文、剧本 Agent、剧本、资产、角景、生产、导出 |
| 多语言 | 新增 `projectOverview`、`route.projectOverview`、`routeDescription.projectOverview/export` |
| 验证 | 新增专项脚本检查路由、菜单、打开项目目标、i18n 和文档记录 |

## 第四批做什么

一句话：流程总览不要只显示“有失败”，还要告诉用户最近失败的是哪些任务，并能一键跳到任务中心筛选当前项目失败任务。

### 要做什么功能 / 怎么做

| 功能 | 怎么做 |
| --- | --- |
| 失败任务摘要 | `project.getFlowStats` 返回 `failedTaskSummaries`，只取当前项目最近 3 条失败任务 |
| 失败原因安全 | 失败原因继续脱敏，流程总览只显示摘要，不展示密钥、token 或完整本机路径 |
| 流程总览提示 | 有失败任务时显示红色阻断提示和最近失败任务卡片 |
| 跳任务中心 | 流程总览点击“查看失败任务”跳到 `tasks?projectId=当前项目&status=failed` |
| 任务中心承接 | 任务中心读取 route query，自动套用项目和失败状态筛选 |
| 职责边界 | 不把任务中心完整表格搬到流程总览；复制失败原因、完整筛选、分页仍在任务中心 |
| 多语言 | 所有新增可见文案写进 `projectOverview.failedTasks` 中英文 |
| 验证 | 新增 `verify-opt-051-task-failure-link.mjs`，并接入 `verify:project` |

### 第四批边界
