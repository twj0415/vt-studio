# OPT-054 上游变更与下游失效规则

## 通俗总结

这一步是防止“旧结果装成新结果”。

用户改了原文、剧本、资产、分镜或视频候选以后，下面已经生成过的资产图、分镜图、视频提示词、视频候选和导出结果不能继续静默显示成完全可用。系统要明确告诉用户：这个结果还有效、需要复查、已经过期、缺依赖，还是被阻断。

## 参考项目怎么做

| 参考位置 | 结论 |
|---|---|
| `Toonflow-app-master/src/routes/taskRecord.ts` | 参考项目记录任务成功失败，但任务状态不等于业务结果是否仍然可信 |
| `Toonflow-app-master/src/routes/assetsGenerate/*` | 资产图依赖资产描述、提示词、参考图、项目配置和手册 |
| `Toonflow-app-master/src/routes/videoGenerate/*` | 视频生成依赖分镜图、视频提示词、视频 mode、参考素材和已选候选 |
| `Toonflow-web-master` 生产相关页面 | 用户会在中途编辑、替换、删除，不是一次性到底 |

VT Studio 要比参考项目更明确：生成状态和依赖可信度必须分开。生成状态表示“有没有跑成功”，依赖状态表示“当前结果还可不可信”。

## 要做什么

1. 新增统一依赖状态：
   - `valid`：当前结果可信。
   - `stale`：上游内容变了，需要重新生成或确认。
   - `needs_review`：结果还能看，但建议复查后再继续。
   - `missing_dependency`：引用的资产、分镜或视频候选不存在，必须修。
   - `blocked`：存在阻断，不允许导出。
2. 数据库加依赖状态字段：
   - `scripts`
   - `assets`
   - `production_storyboards`
   - `production_video_tracks`
   - `production_videos`
3. 原文章节正文变化：
   - 章节事件继续标记 `stale`。
   - 同项目剧本标记 `stale`，原因说明“原文已变更”。
   - 不删除旧剧本。
4. 剧本正文变化：
   - 当前剧本标记 `valid`。
   - 资产提取状态回到 `idle`。
   - 该剧本的分镜、视频轨道、视频候选标记 `needs_review`。
5. 资产变化：
   - 修改资产描述、提示词或选择图片后，引用它的分镜、视频轨道、视频候选标记 `needs_review`。
   - 删除资产后，引用它的分镜、视频轨道、视频候选标记 `missing_dependency`。
6. 分镜变化：
   - 修改分镜文案、提示词、关联资产或分镜图后，所在视频轨道和视频候选标记 `needs_review`。
   - 删除分镜后，所在视频轨道和视频候选标记 `missing_dependency`。
7. 视频候选变化：
   - 删除已选视频候选时，清空轨道选择，并把轨道标记 `missing_dependency`。
   - 重新生成成功的视频候选标记 `valid`。
   - 选择已完成视频候选后，轨道标记 `valid`。
8. 导出校验：
   - `missing_dependency`、`blocked` 必须阻止导出。
   - `stale`、`needs_review` 第一版也阻止导出，后续再做“确认继续使用旧结果”的显式入口。
9. 页面提示：
   - 资产中心显示资产依赖状态和原因。
   - 生产工作台显示分镜、轨道、视频候选依赖状态和原因。
   - 导出页显示依赖失败原因。

## 具体怎么做

1. 在 `src/shared/constants/dictionaries.ts` 增加依赖状态字典。
2. 在 `src/shared/constants/status-layers.ts` 增加 `DEPENDENCY_STATE` 层，明确它不是任务状态。
3. 在 `src/main/services/production/migrations.ts` 增加字段迁移。
4. 新增 `src/main/services/dependency-state.ts`：
   - 统一判断依赖状态。
   - 统一更新 scripts、assets、storyboards、tracks、videos。
   - 提供“资产影响生产”“分镜影响视频”“剧本影响生产”的 helper。
5. 修改原文、剧本、资产、生产服务：
   - 编辑/删除/生成成功时调用依赖状态 helper。
   - 不把依赖状态写进任务状态字段。
6. 修改导出服务：
   - 构建时间线前检查轨道和已选视频依赖状态。
   - 素材校验时检查相关分镜依赖状态。
7. 修改共享类型和页面：
   - mapper 返回 `dependencyStatus`、`dependencyReason`。
   - 页面用 tag 展示，不写中文硬编码。
8. 新增专项 verify：
   - 检查字典、迁移、helper、服务调用、导出校验、页面 i18n 和 TODO 状态。

## 不做什么

1. 不做复杂的“用户确认继续使用旧结果”入口；本任务先阻止导出，确认入口后续可以单独做。
2. 不做导出历史；这个归 `OPT-056`。
3. 不做孤儿文件清理；这个归 `OPT-036`。
4. 不伪造原文章节到剧本的精确映射；当前没有映射表，所以原文变化只保守标记同项目剧本。

## 完成标准

1. 上游变更后，下游对象不会继续只有“成功”一种表现。
2. 生成状态和依赖状态分开，不互相污染。
3. 页面能看到需复查、已过期、缺依赖及原因。
4. 导出前能阻止缺依赖和未复查结果。
5. 重新生成或重新选择后，对应对象能恢复 `valid`。
6. verify、typecheck、build 通过。
