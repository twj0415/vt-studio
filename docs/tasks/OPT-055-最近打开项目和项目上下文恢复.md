# OPT-055 最近打开项目和项目上下文恢复

状态：已完成

一句话：用户打开过项目后，刷新窗口或重启应用，不应该因为前端内存丢失就被打回项目列表。

## 要做什么功能 / 怎么做

| 功能 | 怎么做 |
| --- | --- |
| 保存最近项目 | `project.open` 成功后写入 `app_settings.recentProject.v1` |
| 保存内容 | 保存 `projectId`、`projectName`、`sourceType`、`lastRoute`、`openedAt`、`updatedAt` |
| 恢复最近项目 | preload 暴露 `project.restoreRecent`，main 校验项目还存在、模型还有效、手册还存在、目录可用 |
| 路由守卫恢复 | 进入项目内路由但 `currentProject` 为空时，先调用 `restoreRecent`，成功后再放行 |
| 启动恢复 | 应用第一次进入项目列表时，如果有最近项目，自动跳到最近的项目内页面 |
| 更新最近路由 | 项目内路由切换后写回 `lastRoute`，下次启动能回到上次停留页面 |
| 删除项目清理 | 删除最近项目时同步清空最近项目记录 |
| 项目页行为 | 进入项目列表不再直接清空 `currentProject`，用户回项目页不等于退出项目 |

## 边界

1. 不新增数据库表，复用 `app_settings`。
2. 不用 `localStorage` 当唯一来源。
3. 不恢复到不存在的 route，非法 route 回到 `project-overview`。
4. 恢复失败不抛到页面崩溃，main 清掉失效记录，前端回项目列表。
5. 不在 renderer 直接查 SQLite。

## 验收标准

1. 打开项目后刷新窗口，仍能留在项目内页面。
2. 重启后第一次进入应用，能恢复最近项目和最近项目内页面。
3. 最近项目被删除后，不会继续恢复到坏项目。
4. 项目模型或手册失效时，不进入坏页面，而是回项目列表。
5. 项目页不再因为 `onMounted` 清空当前项目。
6. `verify:project`、`typecheck`、`verify:docs`、`build` 通过。
