# P13 真实模型适配与端到端生成验收批

状态：已完成  
覆盖范围：模型连接运行时、媒体模型测试、默认 adapter 空实现防护、P9-P10 真实生成验收前置条件  
前置任务：P11 真实数据验收批、P12 真实生成执行器批

## 0. 快速理解

```txt
一句话：保证用户配置真实 API 后，文本/图片/视频模型能从普通入口和生产链路真实调用；没配置、未实现或返回无效媒体时必须明确失败。
为什么现在做：P12 已把 P9 生成链路接到 generateImageByModel/generateVideoByModel，但模型接入层如果还会空返回或普通入口不能测试媒体，就无法做端到端验收。
做完后有什么用：真实 API 由用户后续提供时，先在模型服务页测通，再进入 P9 生成图片/视频，最后用 P10 导出。
这一步不碰什么：不新增演示数据，不替用户配置真实密钥，不伪称真实 API 已跑通。
```

## 1. 问题

```txt
P12 完成后，主链路还存在几个真实验收风险：
1. 连接行 conn_* 复用高级供应商 adapter 时，runtime.vendor 可能被替换对象，导致脚本闭包读取不到数据库保存的 inputValues。
2. 普通模型服务连接原本只走内置连接 runtime，atlascloud/minimax/volcengine 等高级 adapter 的图片/视频实现无法复用到普通入口。
3. 部分默认 adapter 用 return "" 或空函数表示未实现，媒体链路可能把空结果当成成功风险。
4. 普通模型服务页第一版只支持文本测试，用户配置 image/video 后不能从普通入口验证。
5. 模型返回空字符串、错误 MIME、过小 base64 或无效 base64 时，需要统一按失败处理。
```

## 2. 实现范围

```txt
1. validateVendorRuntime 保留原 vendor 对象引用，并用 Object.assign 注入规范化结果。
2. conn_* 连接运行时可复用高级 adapter，并把连接保存的 API Key/Base URL/models 注入 runtime.vendor。
3. atlascloud 连接从普通 Base URL 自动推导 chatBaseUrl/mediaBaseUrl。
4. generateImageByModel/generateVideoByModel/generateAudioByModel 统一校验媒体返回值。
5. 普通模型服务页支持默认能力 image/video 测试，结果展示生成文件路径和耗时，不展示整段 base64。
6. settings.api.test 支持普通连接的 text/image/video 测试，TTS 仍明确提示未接入测试入口。
7. 默认 adapter 模板未实现能力全部显式 throw，不再用空字符串或空函数表示成功。
8. 新增 P13 专项验证脚本，防止模型适配层回退。
```

## 3. 不做范围

```txt
1. 不写 vt_demo_*、vt-demo-image、vt-demo-video 或 [演示] 数据。
2. 不替用户填写真实 API Key。
3. 不声明已真实跑通外部 API；只能保证配置真实 API 后代码链路可执行，缺配置时明确失败。
4. 不在本批实现 TTS 测试入口。
5. 不改变 P10 第一版导出边界；真实剪映 schema、WebAV mp4、完整 ComfyUI workflow 仍后置。
```

## 4. 技术方案

```txt
1. vendor-runner：
   - validateVendorRuntime 使用 Object.assign(runtime.vendor, normalizedVendor)
   - 保留 adapter 脚本闭包里引用的 vendor 对象
2. vendor-service：
   - 新增 createConnectionRuntimeFromAdapter
   - 连接行读取 __adapterVendorId 后复用真实 adapter runtime
   - 注入 connectionId、connectionName、inputValues、models
   - atlascloud 自动补 chatBaseUrl/mediaBaseUrl
3. media：
   - normalizeMediaResult 校验 URL/data URL/base64
   - 空返回、错误 MIME、无效 base64、过小内容全部 MODEL_ERROR
4. settings model-config：
   - testApiConnection 按模型类型分发 text/image/video
   - testResourceBinding 复用 testApiConnection
5. renderer ModelServiceConfig：
   - 默认能力卡测试不再限制 text
   - 已连接服务卡优先选择 text/image/video 可测模型
   - image/video 只展示 filePath，不展示 content base64
6. 默认 adapter：
   - 未实现的 imageRequest/videoRequest/ttsRequest/textRequest/updateVendor 改为 throw
   - null 模板文档改为“未实现必须 throw”
```

## 5. 验收标准

```txt
1. P13 专项验证脚本通过。
2. P12 真实生成执行器回归通过。
3. typecheck 通过。
4. build 通过。
5. resources/default-data/vendors 下不再存在 adapter 空实现 return "" 或 => {}。
6. 普通模型服务页没有“媒体测试后续接入”的阻塞文案。
7. 真实 API 未配置时，模型测试和 P9 生成必须失败并给出明确原因。
```
