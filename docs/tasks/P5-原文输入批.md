# P5 原文输入批

状态：已完成  
覆盖范围：F-004-001 到 F-004-007  
对应功能文档：`docs/features/M-004-小说原文.md`

## 1. 合并结论

P5 不再按 7 个单 task 分开实现。

原因：

```txt
1. 导入、列表、编辑、删除、事件分析、轮询和事件查看共享同一套 source_chapters 数据结构。
2. 拆开实现会反复修改 main service、IPC、preload、页面、i18n 和样式。
3. 事件分析依赖章节表、模型调用和任务中心，必须一次收口状态和失败原因。
4. 参考项目的独立事件库没有完整闭环，第一版不能按旧 event.vue 拆出第二套事件来源。
```

## 2. 本批次一次完成什么

```txt
1. 原文真实页面，不再使用占位 scaffold。
2. 原文章节表、分页、章节名搜索、正文和事件摘要预览。
3. txt 文件导入、粘贴文本导入、章节解析、预览勾选和保存。
4. 章节编辑，支持卷名、章节名、正文、事件摘要；正文变更后标记需重新分析。
5. 单条删除和批量删除，生成中章节禁止删除。
6. 选中章节触发事件分析，状态变为 running，模型调用在 main 侧执行。
7. 事件状态 3 秒轮询，完成或失败后更新表格。
8. 应用启动时修复残留 running 事件状态。
9. 事件分析写入任务中心，失败原因进入章节和任务记录。
```

## 3. 明确不做

```txt
1. 不做 doc 文件导入。
2. 不保存原始导入文件副本。
3. 不做正文全文搜索、卷名搜索、事件内容搜索。
4. 不做旧 event.vue 的独立事件列表库。
5. 不调用不存在的 /novel/event/eventAnalysis。
6. 不做剧本 Agent、剧本生成或剧本结果写入。
7. 不在 renderer 直接访问 SQLite、文件系统或模型 SDK。
```

## 4. 关键取舍

### 4.1 UI 文案使用“原文”

菜单和页面显示使用“原文”。文档继续保留“小说/原文”的映射，避免和参考项目事实断开。

### 4.2 第一版不保存原始文件副本

参考项目只读取 txt/docx 文本，不保存源文件。P5 第一版先对齐这个语义，只保存解析后的章节正文，避免引入项目文件生命周期和重复清理问题。

### 4.3 第一版以章节级事件摘要为准

参考项目主列表使用 `o_novel.event`，旧 `event.vue` 的事件库没有找到主页面挂载和同步闭环。P5 第一版只做章节级事件摘要：

```txt
source_chapters.event_summary
source_chapters.event_status
source_chapters.event_error
```

后续如果要做独立事件库，必须重新设计事件和章节的同步规则。

### 4.4 事件分析进入任务中心

Toonflow 没有把事件分析写入 `o_tasks`，但 VT Studio 已完成任务中心。事件分析是模型异步任务，必须可观测，所以 P5 会写任务记录：

```txt
category: 原文事件分析
related_objects: { chapterIds }
status: running/succeeded/failed
```

章节状态和任务状态分开维护：章节逐条成功或失败，任务代表本次批量分析整体完成情况。

### 4.5 模型调用走已有文本模型服务

P5 不让 renderer 直接调用模型 SDK。事件分析在 main 侧读取提示词和章节正文，走现有文本模型适配层。模型未配置、提示词异常、空输出都写失败原因。

### 4.6 章节解析支持 txt、docx 和粘贴文本

P5 不新增 docx 解析依赖；renderer 直接读取 docx zip 包中的 `word/document.xml`，提取纯文本后复用同一套章节解析。旧 `doc` 格式不支持。

## 6. 实现方案

```txt
1. 新增 shared/types/source.ts，统一章节、导入、列表、编辑、删除、轮询、事件分析 DTO。
2. 新增 main/services/source/migrations.ts 和 service.ts，创建 source_chapters 表。
3. source.importChapters 按当前项目最大 chapter_index 继续累加，新增章节默认 event_status=stale。
4. source.listChapters 支持 projectId、chapterKeyword、page、limit，只查当前项目。
5. source.updateChapter 在正文变更时清空旧事件摘要并标记 stale。
6. source.deleteChapters 事务删除章节，running 状态阻断。
7. source.generateEvents 创建任务记录，把选中章节置 running，并在后台按设置并发调用模型生成事件摘要。
8. source.pollEventStatus 只返回已离开 running 的章节。
9. main 启动迁移后执行 recoverRunningSourceEvents，把残留 running 章节改 failed。
10. 新增 main/ipc/source.ts，preload 暴露 window.vtStudio.source。
11. NovelHome.vue 替换为真实原文页面，包含导入、列表、编辑、删除、事件分析和轮询。
12. messages.ts 和 styles/index.scss 补原文页面文案与样式。
13. scripts/verify-p5-source.mjs 检查迁移、IPC、preload、页面和关键文案。
```

## 7. 验收

```txt
1. 原文菜单能进入真实页面。
2. 没有当前项目时显示空状态，不发起业务写入。
3. txt、docx 或粘贴文本能解析章节；无章节匹配时全文作为一章。
4. 解析预览必须勾选章节才能保存。
5. 保存后列表刷新，章节按 chapter_index 展示。
6. 搜索只按章节名生效，分页生效。
7. 正文和事件摘要长内容可查看详情。
8. 编辑正文后旧事件摘要不会继续被当作有效摘要。
9. 单条删除和批量删除有确认，running 章节不能删除。
10. 选中章节可触发事件分析，生成中显示 loading。
11. 轮询成功后显示事件摘要，失败后显示失败原因。
12. 事件分析任务能进入任务中心。
13. typecheck、build、专项 verify 通过。
```
