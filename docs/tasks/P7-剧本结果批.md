状态：已完成  
覆盖范围：F-005-001 到 F-005-008  
对应功能文档：`docs/features/M-005-剧本.md`

## 1. 合并结论

P7 不再把 F-005-001 到 F-005-008 拆成 8 个小 task 逐个实现。

原因：

```txt
1. 新增、编辑、搜索、删除、导出和资产提取都围绕同一个 scripts 表和同一个剧本列表页。
2. 如果逐个拆分，会反复改 ScriptHome.vue、script service、preload 契约、i18n 和样式。
3. P6 已经建立 scripts 表，P7 必须复用它作为剧本真实来源，不能再建第二套剧本数据。
4. 资产提取和状态轮询必须和任务中心、失败原因、启动恢复一起收口，否则状态容易卡住。
```

## 4. 关键取舍

### 4.1 复用 P6 scripts 表

P6 已经建立 `scripts` 表，P7 继续使用同一张表作为剧本真实来源。

```txt
新增/编辑/批量导入 -> scripts
Agent XML 写入 -> scripts
P7 列表/导出/资产提取 -> scripts
```

这样 P6 Agent 工作区和 P7 剧本结果页不会出现两套剧本数据。

### 4.2 最小资产表先落地

P7 需要手动关联资产和 AI 提取资产，所以先新增：

```txt
assets
script_asset_links
```

完整资产中心 UI、素材预览、图片生成、音频资产继续归 P8。

### 4.3 资产提取进入任务中心

Toonflow 的资产提取没有写任务中心。VT Studio 已经有任务中心，P7 统一写：

```txt
category: 剧本资产提取
modelName: universalAi
status: running/succeeded/failed
relatedObjects: { scriptIds }
```

这是功能增强，不改变业务语义。

### 4.4 waiting/running 启动恢复

参考项目只恢复正在提取状态。VT Studio 同时恢复：

```txt
waiting
running
```

原因是桌面端退出时 waiting 也不可能自动恢复执行，继续显示等待会误导用户。

### 4.5 批量资产关联按 scriptIds 落库

模型提取结果必须带 `scriptIds`。如果模型没有返回有效 `scriptIds`，才回退到本批全部剧本。

这避免批量提取时把某个剧本独有的角色、场景或道具误关联到所有选中剧本。
