# P9 生产工作台源码对齐分析

状态：分析完成，待按本文进入实现  
范围：Toonflow 生产页主画布、图片工作流、分镜面板、视频生成工作台、Production Agent 工具、后端 production routes  
原则：参考项目有的功能不能少；参考项目设计不稳的地方不能照搬，要在 VT Studio 中用更清晰的数据表、service、IPC 和任务中心实现。

## 1. 结论

P9 是短剧生成主链路，不是普通列表页。最低目标不是“能生成视频”，而是要形成完整生产闭环：

```txt
剧本 -> 导演计划 -> 资产/衍生资产 -> 分镜表 -> 分镜面板 -> 图片工作流 -> 视频轨道 -> 视频候选 -> 已选候选 -> P10 导出
```

参考项目 Toonflow 已经具备较完整的生产链路，但存在状态混乱、删除不彻底、业务事实混在 flowData、轨道 id 用 Date.now、视频成功状态不统一等问题。VT Studio 应保留它的所有业务能力，但正式实现不能照搬这些缺口。

## 3. 主画布必须包含的功能

Toonflow 主生产页使用 Vue Flow。VT Studio 不能退化成普通卡片流或列表。

必须包含：

```txt
1. 剧本/分集选择，默认选中当前项目第一个剧本。
2. 无剧本时明确空状态，不渲染假流程。
3. 切换剧本后重建生产上下文。
4. Vue Flow 画布、节点、连线、拖拽、缩放、背景、控制器、小地图。
5. 自动布局：LR 主链布局，复杂布局可用 dagre。
6. 节点坐标保存，刷新数据后位置不回跳。
7. 刷新 flowData，从数据库事实表重建，而不是只读快照。
8. 保存 flowData，只保存文本、坐标和工作区快照，不覆盖资产/分镜/视频事实。
9. 空格 + 鼠标拖动画布，拖拽/平移时降低重渲染压力。
10. Production Agent 面板入口。
```

节点和连线：

```txt
script -> assets
script -> scriptPlan
scriptPlan -> storyboardTable
storyboardTable -> storyboard
storyboard -> workbench
```

参考项目有 `poster` 注释代码，但未启用。P9 不把海报当正式节点。

## 4. 每个节点必须包含的功能

### 4.1 script 节点

```txt
1. 展示当前剧本正文。
2. 支持 Markdown 弹窗编辑。
3. 编辑弹窗宽度接近 90vw。
4. 禁止粘贴/拖拽图片和视频进入 Markdown。
5. 保存后写入工作区服务。
```

VT Studio 实现建议：

```txt
剧本正文以 scripts 表为准。
生产页保存 script 内容时，应复用 script service，而不是把剧本只存进 production_workspaces。
```

### 4.2 scriptPlan 节点

```txt
1. 展示导演计划 Markdown。
2. 空状态明确。
3. 支持弹窗编辑和保存。
4. Production Agent 能写入该字段。
```

VT Studio 实现建议：

```txt
scriptPlan 存 production_workspaces.script_plan。
Agent 写入必须走 service 校验，不能直接改前端状态。
```

### 4.3 assets 节点

```txt
1. 展示父资产图、名称、描述、类型、原始资产标签。
2. 展示每个父资产下的衍生资产列表。
3. 衍生资产支持空状态、生成中、生成失败、成功图。
4. 失败 tooltip 显示 errorReason。
5. 衍生资产支持新增、更新、删除。
6. 衍生资产点击打开图片工作流。
7. 保存衍生图后写回资产图片和 flowId。
8. 批量生成衍生资产图片，生成状态可轮询。
```

衍生资产生成必须保留：

```txt
1. 根据父资产类型 role/tool/scene 选择对应视觉手册。
2. 先用文本模型为衍生资产生成或补全 prompt。
3. 父资产图片作为 reference。
4. 再用图片模型生成衍生图。
5. 成功写图片路径、状态、prompt。
6. 失败写 errorReason。
```

### 4.4 storyboardTable 节点

```txt
1. 展示 Markdown 分镜表。
2. 空状态明确。
3. 支持弹窗编辑和保存。
4. Production Agent 能写入该字段。
```

### 4.5 storyboard 节点

必须包含：

```txt
1. 分镜网格。
2. 缩放比例控制。
3. 单选、多选、全选、清空选择。
4. 单删和批删。
5. 左右插入新分镜。
6. 编辑 prompt 和 videoDesc。
7. 显示编号、图片、生成中、失败、未生成状态。
8. 失败原因可见。
9. 点击图片或空状态打开图片工作流。
10. 分镜可关联资产，并保留关联资产顺序。
11. 批量生成分镜图片。
12. 强制生成分镜图片。
13. 网格预览和下载预览。
```

分镜图片生成必须保留：

```txt
1. 读取分镜 prompt。
2. 读取项目 imageModel、imageQuality、videoRatio、artStyle。
3. 读取关联资产图片作为 referenceList。
4. shouldGenerateImage=false 时普通批量生成跳过并保持未生成。
5. compulsory=true 时强制生成。
6. 生成状态进入任务中心。
7. 成功写 imageUrl、status=succeeded。
8. 失败写 status=failed 和 errorReason。
```

### 4.6 workbench 节点

必须作为进入全屏工作台的入口，不能只是占位。

Toonflow 工作台有三种模式：

```txt
1. 快速预览。
2. 视频生成。
3. 视频编辑器。
```

VT Studio P9 的取舍：

```txt
1. 快速预览保留。
2. 视频生成必须完整做。
3. 视频编辑器可以先作为入口和结构保留，但不把它作为 P10 导出的唯一依据。
```

原因：参考项目视频编辑器“导入到剪辑台”函数是空实现，不能把它当成已完成闭环。

图片工作流是核心能力，不能退化成单个上传框。

必须包含：

```txt
1. 全屏 Vue Flow。
2. 节点类型：upload、generated。
3. upload 节点支持选择资产图、选择分镜图。
4. generated 节点支持选择资产图、选择分镜图、本地上传。
5. 节点连线。
6. 删除连线。
7. 删除节点。
8. 自动布局。
9. 连线变化后，自动把上游节点图片同步为 generated.references。
10. generated 节点支持 promptEditor。
11. generated 节点支持模型、比例、质量选项。
12. generated 节点可调用图片模型生成。
13. 保存工作流 flowData。
14. 更新已有工作流 flowData。
15. 保存最终图时写回调用方，调用方可能是衍生资产或分镜。
```

节点数据：

```txt
upload.data.image
generated.data.generatedImage
generated.data.references[]
generated.data.prompt
generated.data.model
generated.data.ratio
generated.data.quality
```

VT Studio 应超过参考项目的点：

```txt
1. production_image_flows 使用明确 project_id/script_id，不存孤立 flow。
2. flowId 使用稳定 id，不依赖外部 JSON 是否完整。

```

## 6. 视频生成工作台必须包含的功能

这是 P9 最关键部分，也是短剧生成主链路的出口。

### 6.1 模型和模式

必须包含：

```txt
1. 视频模型选择。
2. 模式选择。
3. 音频开关。
4. 分辨率选择。
5. 时长选择。
6. 轨道时长按模型允许值 clamp。
7. 模式切换时，如果已有素材或 prompt，需要确认后清空。
```

Toonflow 支持的视频模式：

```txt
singleImage
startEndRequired
endFrameOptional
startFrameOptional
text
videoReference:N
imageReference:N
audioReference:N
textReference:N
```

其中多参考模式以数组组合出现，例如：

```txt
["imageReference:3","audioReference:1"]
["videoReference:1","imageReference:2"]
```

VT Studio 要做得更清楚：

```txt
1. mode 存结构化 JSON，而不是前端到处 JSON.stringify/JSON.parse。
2. 明确每种模式需要的 reference 类型和数量。
3. 生成前校验 reference 数量、类型、是否有 src。
4. text 模式不要求上传图。
5. 首尾帧模式固定两个槽位，并标清首帧/尾帧是否可选。
```

### 6.2 参考素材选择

必须包含：

```txt
1. 从资产选择 role/tool/scene/clip/audio。
2. 从分镜选择已有分镜图。
3. 单图模式最多一张。
4. 首尾帧模式固定首帧、尾帧两个槽位。
5. 多参考模式可追加多个 image/video/audio。
6. 资产绑定音频时自动带出对应音频资产。
7. 素材卡显示来源：storyboard 或 assets。
8. 素材支持图片、视频、音频、纯文本占位。
9. 素材可删除。
```

### 6.3 promptEditor

参考项目使用 `promptEditor`，不能退化成普通 textarea。

必须包含：

```txt
1. prompt 文本编辑。
2. 引用素材预览。
3. 支持图片、视频、音频、文本引用。
4. 保存时能还原 prompt 和引用对象。
5. prompt 失焦自动保存到 track。
```

### 6.4 轨道管理

必须包含：

```txt
1. 轨道列表。
2. 当前轨道切换。
3. 轨道缩略图。
4. 新增轨道。
5. 删除轨道。
6. 单选、多选、全选。
7. 已选视频标记。
8. 批量下载选中轨道的已选视频 zip。
9. 批量生成提示词。
10. 批量生成视频。
11. 当前轨道素材缓存，切换轨道不丢未提交素材。
```

VT Studio 应超过参考项目的点：

```txt
1. 轨道 id 用数据库自增或 UUID，不用 Date.now。
2. 删除轨道要清理候选视频、文件、分镜关联，不只删除 track。
3. track.selected_video_id 作为唯一正式选择字段，不再同时出现 videoId/selectVideoId。
4. 轨道和分镜绑定要有稳定关系表或明确字段。
```

### 6.5 视频提示词生成

必须包含：

```txt
1. 单轨生成视频提示词。
2. 批量生成视频提示词。
3. 根据 model + mode 选择对应提示词模板。
4. 输入信息包含模型名、分镜 videoDesc、duration、关联资产、音频绑定。
5. 状态可轮询。
6. 失败原因可见。
```

参考项目模板选择逻辑：

```txt
1. 先查 modelPrompt 绑定。
2. 未绑定时按模型名和 mode 匹配：
   wan2.6 -> wan2.6Single-imageFirstFrameMode.md
   seedance 2.0 -> seedance2Multi-parameterMode.md
   首尾帧模式 -> universalFirstAndLastFrameMode.md
   多参考模式 -> universalMulti-parameterMode.md
3. 再兜底 videoPromptGeneration 默认提示词。
```

VT Studio 应保留模板选择能力，但实现上复用现有 `model-prompt` 和 `prompt` service。

### 6.6 视频候选生成

必须包含：

```txt
1. 单轨生成视频。
2. 批量生成视频。
3. uploadData/referenceList 按当前 mode 裁剪和校验。
4. 生成参数包含 prompt、model、mode、resolution、duration、audio、aspectRatio。
5. 每次生成创建一个新候选视频。
6. 候选状态：running/succeeded/failed/cancelled。
7. 状态轮询。
8. 失败原因 tooltip。
9. 候选删除。
10. 候选下载。
11. 候选播放预览弹窗。
12. 候选首帧封面。
13. 选择候选视频，写回 track.selected_video_id。
```

P10 导出只能读取已选候选视频，不能随机取第一个候选。

## 10. 数据建模要求

已新增的表方向是正确的，但实现时要补足字段和关系。

正式事实表：

```txt
production_workspaces
production_storyboards
production_storyboard_asset_links
production_video_tracks
production_videos
production_image_flows
assets / asset_media / script_assets 复用现有资产域
tasks 复用任务中心
```

关键原则：

```txt
1. production_workspaces 只存 scriptPlan、storyboardTable、positions_json 等快照。
2. storyboards 是分镜事实。
3. video_tracks 是短剧轨道事实。
4. videos 是候选视频事实。
5. image_flows 是图片工作流事实。
6. flowData 每次由事实表重建，不作为唯一事实来源。
7. 状态统一使用 idle/running/succeeded/failed/cancelled。
```

建议补强字段：

```txt
production_videos:
  mode_json
  reference_json
  resolution
  audio_enabled
  cover_relative_path
  task_id

production_video_tracks:
  sort_index
  mode_json 或使用当前项目默认 mode

production_storyboards:
  task_id
  track_group/name 可选，用于 Agent 分组再绑定 track

production_image_flows:
  owner_type
  owner_id
```

## 11. 参考项目源码问题，VT Studio 不能照搬

```txt
1. 中文状态混用：已完成、生成成功、生成中、未生成。
2. o_videoTrack 同时出现 videoId/selectVideoId，实际字段混乱。
3. addTrack 用 Date.now 作为 id。
4. addStoryboard 接收 shouldGenerateImage 但写库时用 src ? 1 : 0。
5. addStoryboard 前端传 flowId，后端 schema 不收，flowId 会丢。
6. batchDelete 不清理空轨道，removeFrame 清理，行为不一致。
7. 删除衍生资产、分镜、视频候选不完整清理文件。
8. generateVideo 查 assets 为空时可能空引用。
9. getGenerateData 项目未配置模型时返回 200 success 文案，不是明确业务错误。
10. generateFlowImage 保存路径格式不统一。
11. Production Agent 的 get_flowData 有 key，但前端事件返回完整 flowData。
12. 视频编辑器导入剪辑台函数为空，不算完整能力。
```

## 12. VT Studio 要超过参考项目的地方

