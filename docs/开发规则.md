# 开发规则

根目录 `AGENTS.md` 优先于本文。

## 通用

1. 先读现有实现，只改当前任务相关文件，不回退用户改动。
2. 优先复用现有类型、服务、组件和数据结构，不为统一外观大范围重构。
3. 生成结果保留模型、Prompt、参数、参考素材、任务和真实错误。
4. 不因重构删除资源、媒体、手册、Prompt、Skill、模型连接、密钥或系统配置。

## 前端

1. 遵守 Front Skill，沿用 Vue 3、TypeScript、TDesign、i18n 和现有组件写法。
2. 异步操作提供 loading、disabled、empty 和 error 状态。
3. 文案简短，错误提示说明原因和下一步；生产工具界面保持紧凑可扫描。
4. 图标使用现有图标库，用户可见文案进入 i18n。

## 数据和生产

1. 主流程固定为 `内容 -> 资源 -> 分镜 -> 分镜画面 -> 视频 -> 导出`。
2. 优先复用 `ProductionStoryboardItem`、`ProductionVideoTrackItem`、视频候选和 `selectedVideoId`。
3. 分镜拆分可选，但新作品至少保存一条真实分镜，不能用空 `storyboardIds` 表示整篇制作。
4. `directorPlan/script_plan` 只做兼容和内部上下文，不作为用户顶部步骤。
5. 视频候选只有成功落盘后才展示；导出只读取用户选中的正式候选。

## 模型调用

模型接入和参数联动遵守 `模型能力审计与设计.md`。前端只做联动，主进程提交 adapter 前必须再次校验。

需要写入业务数据的 AI 结果统一调用 `src/main/services/model/structured.ts`：

```text
resultTool -> 首次文本 JSON -> JSON-only retry -> normalize -> validate -> diagnostics
```

业务步骤只提供 schema、兜底示例、字段兼容、归一化和业务校验，不复制底层解析与重试。普通文本提示词生成不要求结构化，但仍需保存调用快照。

## 文档和验证

- `docs/README.md` 只做入口。
- `项目功能清单.md` 只写已有功能。
- `后续目标与待办.md` 是唯一 TODO。
- 不保留旧方案和参考项目长文。

必须使用本机 pnpm：

```text
D:\software\nodejs\pnpm.cmd run verify:docs
D:\software\nodejs\pnpm.cmd run typecheck
D:\software\nodejs\pnpm.cmd run build
D:\software\nodejs\pnpm.cmd run verify:production
```

文档改动运行 `verify:docs`；前端或类型改动运行 `typecheck`；主进程、preload 或跨模块改动运行 `build`；生产链路改动补充 `verify:production`。
