# 当前项目对比参考项目还不够的地方

本文只记录当前 VT Studio 相比参考项目 Toonflow 还不够的地方，用于后续产品和开发收口。

先说明结论：当前项目不是整体落后。当前项目在 contentId 合同、Production Tools、审计、剪映草稿导出、导出历史、生产接口正规化方面更正式。本文只列不足，不重复列已经完成或当前项目更强的部分。

## 1. 资源提取还不够可控

当前画布里的资源提取更像“全部提取/重试提取”。提取完成后，资源会进入资源库，并且在画布上展示较多资源节点。

参考项目的资源提取也不是完整的保存前逐项确认，但它的边界更清楚：资源提取主要负责把角色、场景、道具提取进资产库，后续编辑、生成图、换图、上传图都在资产库里完成。

当前不足：

- 没有资源提取结果审核面板。
- 没有按单个资源项重新提取。
- 没有提取前编辑名称、描述、Prompt、类型。
- 没有与已有资源做合并、替换、跳过。
- 提取后画布容易堆出大量资源节点，干扰主生产流程。
- 资源库和画布边界不够清楚，画布承担了太多资产管理职责。

建议方向：资源提取应改成“提取草稿 -> 审核/编辑/合并 -> 入库 -> 画布只引用关键资源”。

## 2. 资源提取缺少选择性保存能力

严格来说，参考项目也没有把“选择性保存”做得很完整，它更多是直接入库。但从当前项目目标和实际体验看，这仍然需要补。

当前不足：

- 用户不能在保存前决定哪些资源要入库。
- 用户不能删除某条 AI 提取错的资源后再保存。
- 用户不能把两个相似角色或道具在入库前合并。
- 用户不能把提取出的资源改类型，例如把错误识别成“道具”的资源改成“场景”。
- 用户不能只保存角色，不保存场景或道具。

建议方向：资源提取结果先进入临时草稿区，不直接写正式资源库；用户确认后再批量入库。

## 3. 资源提取缺少单项重跑

当前更偏整体提取和整体重试。参考项目虽然资源提取也偏批量，但在后续资产图、分镜图、视频生成环节有较多单项重新生成能力。

当前不足：

- 不能只重新提取某个角色、场景或道具。
- 不能针对某条资源给出补充要求后重新提取。
- 不能保留其他正确资源，只替换错误资源。
- 不能对单项错误结果做“重新提取但不影响其他资源”。

建议方向：每条资源草稿都应有“重新提取”“编辑”“合并到已有资源”“删除”“确认入库”。

## 4. 图片工作流只是外壳，没有真实生成闭环

参考项目的图片工作流可以真实调用生成接口，生成图片后点击“保留”回写到分镜图或衍生资源图。

当前项目已经有图片工作流弹窗，包含上传节点、生成节点、参考图、Prompt、模型、比例、质量、保存、应用结果等元素。

当前不足：

- 没有真正执行图片生成的后端接口。
- 没有明确的“生成图片”按钮闭环。
- 生成结果目前更像手动填写 URL 后再应用。
- 没有生成候选图列表。
- 没有候选图选择保留。
- 没有候选图删除。
- 没有生成失败后的单张重试。

结论：当前图片工作流具备界面骨架，但还不是完整的生产能力。

## 5. 分镜图缺少单张精修闭环

参考项目里，分镜图可以打开图片工作流，单张调整 Prompt、参考图、模型、比例，然后重新生成并保留。

当前不足：

- 分镜图不能真正进入“单张生成 -> 多候选 -> 选择保留”的完整流程。
- 分镜图生成后缺少候选版本管理。
- 分镜图失败后缺少单张重试和诊断。
- 分镜图使用了哪些角色、场景、道具、手册规则，展示不够直观。

建议方向：分镜图应支持每张图独立打开图片工作流，并能把新生成结果作为候选版本保存。

## 6. 衍生资源图缺少单张精修闭环

衍生资源包括风格图、关键物件图、特殊场景图、参考图等。参考项目可以对这类资源进行生成和保留。

当前不足：

- 衍生资源图生成链路不够完整。
- 衍生资源图缺少候选版本。
- 不能清楚看到每张衍生资源图来自哪个 Prompt、模型、参考素材。
- 不能方便地重新生成某一张衍生资源图。

建议方向：衍生资源也应进入图片工作流，并和分镜图一样支持候选、保留、回写、重试。

## 7. 资产库候选图管理粒度不够

当前资产库已经有角色、场景、道具、视频片段、音频，也支持资产编辑、图片生成、历史图选择、上传媒体。

但和参考项目相比，候选图管理还不够细。

当前不足：

- 历史候选图缺少每张图独立删除入口。
- 当前更偏选择历史图和删除最新图，不是完整候选图网格管理。
- 缺少多张候选图横向对比体验。
- 每张图的 Prompt、模型、参数、生成时间展示不够清楚。
- 用户不容易判断当前使用的是哪张图、上一版是哪张图。

建议方向：资产详情中应有“候选图历史”，每张候选图都能选择、删除、查看生成信息。

## 8. 视频工作台的生成模式还不够细

参考项目的视频生成模式更细，包括文生视频、单图视频、首尾帧、首帧可选、尾帧可选、多参考素材等。

当前项目已经有视频提示词生成、视频生成、候选选择、参考素材选择，但体验还不够细。

当前不足：

- 不同视频模式下的输入槽位不够明确。
- 首帧、尾帧、多参考素材的 UI 区分不够强。
- 单图视频和多参考视频的素材限制提示不够直观。
- 用户不知道当前模式必须提供哪些素材。
- 不同模型支持的参考素材数量、类型、比例限制展示不够清楚。

建议方向：视频工作台应按模型能力和生成模式展示专用槽位，而不是只做通用多选。

## 9. 视频参考素材自动聚合不够明显

参考项目会把分镜、角色、场景、道具、视频片段、音频等素材组织进视频生成上下文，部分场景下还会把角色绑定音频纳入参考。

当前项目已有参考素材选择，但自动聚合体验不够明显。

当前不足：

- 分镜关联的角色、场景、道具是否自动参与视频生成不够直观。
- 角色绑定音频是否自动参与视频生成不够直观。
- 参考素材来源和用途没有清楚分层。
- 用户需要更多手动选择，系统自动补全能力不够强。

建议方向：视频轨道应自动带出本分镜相关素材，并允许用户删除或替换。

## 10. 视频候选管理还不够完整

当前项目已经有视频候选、预览、选择候选。

不足在于候选管理和追溯还不够完整。

当前不足：

- 单条候选的删除、下载、重新生成入口不够清楚。
- 失败候选和成功候选的诊断信息展示不够直观。
- 候选视频和 Prompt、模型、参考素材、参数之间的关系展示不够清楚。
- 批量生成后，缺少逐条修复和逐条重试体验。
- 用户不容易知道当前选中候选和其他候选的差异。

建议方向：每条视频轨道应有候选列表，候选项显示生成参数、参考素材、Prompt、状态和操作。

## 11. 剪辑台能力明显不如参考项目

这是当前项目和参考项目相比最明显的体验差距之一。

参考项目有 WebAV 和时间线剪辑台，支持视频、音频、图片、贴纸、字幕、文本等 clip，能拖拽时间线、调整轨道、预览并导出浏览器 MP4。

当前项目的导出更正式，支持剪映草稿，这是优势。但当前工作台更像“轨道列表 + 已选视频 + 导出入口”，不是完整剪辑台。

当前不足：

- 没有可视化时间线拖拽。
- 没有完整多轨道编辑。
- 没有音频轨、字幕轨、贴纸轨、图片轨混剪。
- 没有 clip 级别的时长、位置、缩放、裁剪、层级编辑。
- 没有实时预览剪辑结果。
- 资产库里的 clip、audio、image、text 不能像剪辑素材一样自由编排。

结论：当前导出工程能力更强，但剪辑交互能力不如参考项目。

## 12. 导出时间线素材丰富度不如参考项目

当前导出主要围绕生产视频轨道里的已选视频，导出成剪映草稿。

参考项目剪辑台能把更多素材纳入时间线，包括视频、音频、图片、字幕、文本、贴纸、片尾和资产库 clip。

当前不足：

- 导出 timeline 主要来自生产视频轨道。
- 资产库里的音频不能作为独立剪辑轨道自由编排。
- 资产库里的 clip 不能作为独立素材自由进入导出时间线。
- 字幕、文本、贴纸等剪辑元素不够完整。
- 导出前缺少完整素材编排能力。

建议方向：剪映草稿导出应继续保留，同时增加一个更完整的时间线编排层。

## 13. Production Agent 的子 Agent 还只是占位

当前项目的 Agent 工程结构更正规，有上下文、工具、审计、校验、修复和工具调用。

但参考项目有更明显的专项 Agent 分工，例如导演计划、分镜表、分镜面板、衍生资源、资产生成、监督等。

当前不足：

- 子 Agent 工具还没有真实执行器。
- 专项 Agent 还不能独立完成导演计划、分镜表、分镜图、衍生资源等任务。
- 当前更像一个决策 Agent 调 Production Tools。
- 多 Agent 协作生产深度不够。

建议方向：先保留当前正规工具体系，再逐步把子 Agent 从 reserved 接成真实执行器。

## 14. 导演手册和视觉手册的影响链路不够显性

当前项目已有手册、Prompt、Skill、生产上下文等概念。

不足是用户不容易看出来手册到底影响了什么。

当前不足：

- 不清楚哪些手册规则影响资源提取。
- 不清楚哪些手册规则影响导演计划。
- 不清楚哪些手册规则影响分镜表。
- 不清楚哪些手册规则影响分镜图。
- 不清楚哪些手册规则影响视频提示词。
- 不清楚哪些手册规则影响视频生成参数。
- 生成结果里没有清楚展示使用了哪些手册、Prompt、Skill。

建议方向：每次生成结果和任务诊断里都应能看到使用过的手册、Prompt、Skill 和关键规则摘要。

## 15. 画布和资源库边界需要重整

参考项目的逻辑更接近：资源归资产库管理，画布主要承接生产节点、分镜、视频和生成动作。

当前项目的问题是资源提取后大量资源进入画布，导致画布像资源列表。

当前不足：

- 画布容易被角色、场景、道具节点占满。
- 关键生产链路不够突出。
- 资产管理和生产编排混在一起。
- 用户难以判断哪些节点是真正的流程步骤，哪些只是资源引用。

建议方向：画布只显示生产流程和必要引用，完整资源管理放到资源库或资源面板。

## 16. 单项重试和局部修复能力不够

参考项目在资产图、分镜图、视频候选等环节有较多单项生成、重试、保留路径。

当前项目更偏整体动作和整体状态。

当前不足：

- 不能方便地只重试一个资源。
- 不能方便地只重试一张分镜图。
- 不能方便地只重试一个衍生资源图。
- 不能方便地只重试一条视频提示词。
- 不能方便地只重试一条视频候选。
- 不能方便地恢复上一版结果。

建议方向：所有生成型能力都应支持“单项重试、查看原因、保留旧版、替换新版”。

## 17. 生成结果的版本感不够强

参考项目虽然工程规范不一定更强，但候选图、候选视频、历史记录给了用户比较明确的版本感。

当前项目也有部分 metadata 和历史，但还没有形成完整版本体验。

当前不足：

- 一个资源的多版 Prompt 不够清楚。
- 一个资源的多张图不够清楚。
- 一个分镜的多版图不够清楚。
- 一个视频轨道的多版候选不够清楚。
- 每个版本对应的模型、参数、参考素材、手册规则不够清楚。
- 用户不容易知道当前选中版本、上一版、废弃版本分别是什么。

建议方向：资源、分镜图、视频候选都应有版本历史和当前选中态。

## 18. 人工可干预点还不够完整

参考项目在体验上给了较多人工介入点，包括资产编辑、Prompt 编辑、图片重新生成、图片保留、分镜编辑、视频 Prompt 编辑、视频候选选择、剪辑台调整。

当前项目已有一部分，但还不够完整。

当前不足：

- 资源提取后不能充分审核和编辑。
- 图片生成候选不能充分选择和保留。
- 单张图精修不够完整。
- 视频模式输入槽位不够明确。
- 剪辑台级别调整不足。
- Agent 生成内容的确认、修复、回写过程不够可视化。

建议方向：AI 自动生成不能直接替代人工确认，关键生产结果都应给用户确认和局部修复入口。

## 19. 任务诊断还没有完全转化成用户可理解的信息

当前项目有任务、审计、快照，这是底层优势。但前端诊断体验还没有完全释放出来。

当前不足：

- 失败时不够直观地说明是哪一步失败。
- 不够直观地展示使用了哪个模型、哪个 Prompt、哪些参考素材。
- 不够方便地从失败任务直接重试。
- 不够方便地只重试当前资源、当前分镜、当前视频轨。
- Agent 工具调用过程还不够用户可读。

建议方向：任务中心应从“状态列表”升级为“生产诊断面板”。

## 20. 项目创建阶段的手册配置体验需要继续确认

参考项目在项目创建和项目配置阶段有视觉手册、导演手册相关入口。

当前项目后端上下文已有手册能力，但项目创建或项目编辑阶段是否已经提供足够清楚的手册配置入口，需要继续核查。

潜在不足：

- 新建项目时用户可能不能直接配置视觉手册。
- 新建项目时用户可能不能直接配置导演手册。
- 用户可能不能清楚知道当前项目正在使用哪套手册。
- 手册和后续生产任务之间的关系可能不够直观。

说明：这一项需要进一步查项目创建和项目设置页面后再最终定性。

## 优先级建议

后续不建议平均用力，建议按下面顺序补：

1. 补资源提取审核面板，支持编辑、合并、选择入库、单项重跑。
2. 补图片工作流真实生成闭环，支持候选图、保留、删除、回写。
3. 重整画布和资源库边界，画布只保留生产流程和必要引用。
4. 细化视频工作台生成模式，补首帧、尾帧、多参考、音频引用槽位。
5. 补候选图和候选视频的版本历史、参数追溯、单项重试。
6. 补时间线剪辑能力，至少先支持视频、音频、字幕的基础编排。
7. 把 Production Agent 子 Agent 从占位接成真实执行器。
8. 把手册、Prompt、Skill 的使用情况展示到生成结果和任务诊断里。

## 一句话结论

当前项目的工程底座比参考项目更正规，但生产体验还没有参考项目细。主要差距集中在资源提取审核、图片精修闭环、视频模式编排、候选版本管理、剪辑台和子 Agent 实际执行能力上。
