# 通用视频生产流程

## 定位

VT Studio 服务短剧、小说推文、古诗动画、图文成片和广告等内容类型，但统一使用：

```text
内容 -> 资源 -> 分镜 -> 分镜画面 -> 视频 -> 导出
```

一个作品对应一条最终视频。内容类型只改变拆分规则和 Prompt，不改变主流程。

## 生产对象

| 对象 | 规则 |
| --- | --- |
| 内容 | 支持导入、粘贴、AI 处理和手动编辑；变更后下游结果需复查 |
| 资源 | 角色、场景、道具、片段和音频；AI 提取先进入草稿审核 |
| 分镜 | 拆分可选，但始终至少保存一条真实分镜，并关联所需资源 |
| 分镜画面 | 支持候选、正式选择、失败定位和单项重试 |
| 视频片段 | 按分镜生成，支持多个候选，只有正式候选进入导出 |
| 导出 | 只读取正式结果，不反向修改上游数据 |

## 核心规则

1. 不拆分时，把整篇内容保存为一条分镜和一个视频片段；新数据不得使用空 `storyboardIds`。
2. 不增加“整段制作/分段制作”前置选择，不保存无必要的模式字段。
3. “导演计划”不得作为用户顶部独立步骤，只能用于智能拆分内部规划、任务追踪、AI 上下文和旧数据兼容。
4. 用户界面统一使用“视频片段”，内部可以继续复用 `videoTrack`。
5. 有正式分镜图时，视频生成默认使用图生视频并带入该图；用户主动选文生视频时才不发送图片。
6. 视频模式、时长、分辨率、参考素材和音频按当前模型能力选择并由主进程校验。
7. 生成成功且媒体已落盘后才加入候选；失败尝试只进入任务和诊断记录。
8. 导出前检查分镜、正式画面、正式视频、引用素材和本地文件是否完整可读。

## AI 和人工确认

资源提取、分镜拆分等落库型结果必须走统一结构化调用；不同步骤只定义自己的 schema、归一化和业务校验。

必须保留的确认点：

- 资源草稿审核入库。
- 分镜结构确认。
- 分镜画面正式候选选择。
- 视频正式候选选择。
- 导出前检查。

## 追溯

资源图、分镜画面、视频候选和导出快照应记录：Prompt、模型、参数、参考素材、规则与手册摘要、任务 ID、生成时间和错误原因。

每个工作台步骤提供“规则与手册”入口，只展示该操作实际读取的内置规则、Skill、Prompt、视觉手册和导演手册。

## 兼容

`directorPlan`、`script_plan`、`storyboardTable`、`videoTrack`、`selectedVideoId` 可以为旧数据继续保留，但新界面不得强化旧流程概念，也不为清理命名推倒重建数据模型。

## 验收

- 主流程和用户文案符合本文。
- 不拆分也能完整生产和导出。
- 每个结果能追溯输入与生成信息。
- 失败任务能定位到具体步骤和业务对象。
